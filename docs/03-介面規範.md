# 手沖咖啡紀錄平台 — 介面規範

> 搭配《01-資料庫規格》與《02-功能規格》使用。
> 本文件定義的是**結構與行為的約束**，以及**必須避免的預設美學**。具體的色票、字級、間距數值由專案負責人在 Figma 決定後回填第 2 節。

---

## 0. 給實作者的硬性約束

1. **不得使用 UI 框架的預設外觀直接交付。** 不得出現未經調整的 Vuetify、Element Plus、Bootstrap 或 shadcn 預設樣式。
2. **不得使用瀏覽器原生的 `alert`、`confirm`、`prompt`。**
3. **手機優先。** 所有版面先在 375px 寬度下設計，再向上擴展。使用者喝咖啡時在手機上。
4. **不得加入未經要求的動畫。** 見第 6 節。
5. 第 1 節列出的視覺陷阱是硬性禁止，不是建議。

## 1. 必須避免的預設美學（重要）

咖啡主題有一組極強的預設聯想，會讓成品看起來像任何一個 AI 生成的咖啡網站。**以下全部禁止：**

- **暖奶油色底（#F4F1EA 附近）＋ 高對比襯線標題 ＋ 陶土色／暖褐色強調色（#D97757 附近）。** 這是目前 AI 生成頁面最常見的組合，用在咖啡題材上更是直接撞題。
- **把「咖啡＝棕色」當成配色起點。** 咖啡的視覺世界遠不只是棕色：濾杯的白瓷與樹脂、不鏽鋼手沖壺的冷灰、玻璃分享壺的透明、磅秤的黑、豆袋的印刷色。
- **全大寫的英文標籤**（LATEST BREWS、MY BEANS）。中文介面裡的全大寫英文小標是純粹的裝飾，不承載資訊。
- **所有內容切成一模一樣的圓角卡片**，統一的圓角半徑、統一的淺灰陰影。

  判準：**卡片邊界必須對應真實的分組語意。拿掉分組概念後卡片仍然存在，那就是裝飾，屬於本條禁止的範圍。**

  表單的分組卡片不違反本條——每張卡片是一個真實的欄位分區，拿掉分區這件事卡片就沒有存在理由。反例是把每一則列表項目、每一段文字都包成同樣的卡片：那些卡片不對應任何分組，只是在切割版面。
- **中間點串接的 meta 字串**（`2024/03/12 · V60 · 15g`）。
- **按鈕與連結文字後面加箭頭**（`查看更多 →`）。
- **每個區塊進場都淡入上滑。**

**替代方向的建議**：這是一個資料密集的記錄工具，不是咖啡品牌形象網站。它的視覺參照應該來自實驗記錄本、儀表板、規格表，而不是咖啡廳菜單。冷靜、資訊密度高、對比清晰，比溫暖手感更符合它的實際用途。

**最終視覺方向由專案負責人決定。** 上述禁令的目的是避免實作者在無指示時滑向預設值。

## 2. 設計 Token

實作在 `assets/css/tokens.css`，**不得在元件中寫死色碼**。本節記錄的是實際值，改動 token 時同步更新這裡。

分成兩層：**色階層**提供原始色，**語意層**指定用途。元件只使用語意層——直接引用色階等同於寫死色碼，因為它同樣沒有表達「為什麼是這個顏色」。

### 2.1 色階層

色彩方向：**綠色為強調色**（取自生豆的顏色，刻意避開「咖啡＝褐色」的預設聯想），暖白為底。三組色階，各 11 階。

| 階 | green（強調） | red（狀態） | sand（中性） |
|---|---|---|---|
| 50 | `#D7DED4` | `#FFE8E5` | `#FFFAEF` |
| 100 | `#CAD7C3` | `#FFDBD5` | `#F0E7D4` |
| 200 | `#ADBFA3` | `#FFB5AA` | `#E1D3B3` |
| 300 | `#8DA581` | `#F18F81` | `#CFBC91` |
| 400 | `#708B62` | `#DA6C5F` | `#BAA26C` |
| 500 | `#516E41` | `#C0453A` | `#A18545` |
| 600 | `#405933` | `#9D352C` | `#846B2F` |
| 700 | `#334727` | `#7F2821` | `#67521F` |
| 800 | `#25331C` | `#5C1D18` | `#4B3B14` |
| 900 | `#172112` | `#3B130F` | `#32270D` |
| 950 | `#0E130C` | `#210D0A` | `#1E1708` |

另有兩個獨立值：`--white` `#FFFFFF`、`--ink` `#2A2E26`、`--ink-muted` `#6B6F63`。

**綠色配白字的對比限制（重要）：**

| 階 | 配白字對比 | 可用性 |
|---|---|---|
| green-300 `#8DA581` | **2.68:1** | ❌ 不可配白字 |
| green-400 `#708B62` | **3.78:1** | ❌ 未達 AA 4.5:1 |
| green-500 `#516E41` | 5.7:1 | ✅ |
| green-600 `#405933` | 7.79:1 | ✅ |

**因此互動狀態往深走，不往淺走**：預設 `green-500` → hover `green-400` → active `green-600`。hover 用 400 是因為那個狀態下不放白字（只有底色變化）；任何會疊白字的狀態一律 500 起跳。

### 2.2 語意層

| Token | 用途 | 值 |
|---|---|---|
| `--bg` | 頁面底色 | `sand-50` |
| `--surface` | 卡片、表單區塊 | `white` |
| `--text` | 主要文字 | `ink`，對比 13.3:1 |
| `--text-muted` | 次要文字、單位 | `ink-muted`，對比 4.9:1 |
| `--text-faint` | 比 muted 再淡一階的附屬文字 | `sand-400` |
| `--settings-icon` | 首頁右上角的設定齒輪（線寬 2） | `sand-600`。`--bg` 上 4.89:1 |

| `--border` | 分隔線、一般邊界 | `sand-100` |
| `--border-strong` | 需要更明顯的次要按鈕 | `sand-400` |
| `--accent` | 主要行動、選取狀態、連結 | `green-500`，在 `--bg` 上 5.5:1、配白字 5.7:1 |
| `--accent-soft` | 圖示、hover、次要狀態 | `green-400` |
| `--accent-active` | 按下狀態 |  `green-600` |
| `--accent-wash` | 選取項目的底色 | `green-50` |
| `--on-accent` | 疊在 `--accent` 上的文字 | `white` |
| `--on-accent-wash` | 疊在 `--accent-wash` 上的文字 | `green-700`，7.38:1。**不可用 `--accent`，那只有 4.18:1** |
| `--favorite` | 愛心 | `red-500` |
| `--danger` | 刪除、錯誤 | `red-700` |

| `--diff` | 差異標記 | `green-600`。主要靠字重表達，顏色為輔 |
| `--overlay-scrim` | 浮層背後的遮罩 | `rgb(0 0 0 / 0.4)`。純黑不取自色階——它的作用是壓暗底下的內容，帶色相會讓底層看起來變色而不是變暗 |
| `--media-bg` | 深色媒體面（照片裁切）的底色 | `ink`。淺色底會讓照片看起來偏暗，裁切時要讀準照片本身的顏色 |
| `--on-media` | 媒體面上的文字 | `white`，13.84:1 |
| `--on-media-danger` | 媒體面上的錯誤文字 | `red-200`，8.20:1。`--danger` 在深底上讀不到 |
| `--media-border` | 媒體面上的次要按鈕邊框 | `sand-400`，5.58:1（非文字元素，門檻 3:1） |

**`--control-empty` 不可以用 `--border` 代替。** 兩者都是「淺淺的一條線」，但用途不同：`--border` 是分隔線與卡片邊界，它不是可以按的東西；`--control-empty` 畫的是**還沒被選取、但可以點**的目標，輪廓就是全部的資訊。這兩個曾經是同一個 token，結果星等的後兩顆空心星在 375px 下幾乎看不見，使用者不知道那裡還有東西可以按（`sand-100` 只有 1.23:1）。

**`--control-empty` 是 `sand-400`，刻意低於 §7 非文字元素的 3:1（2026-09-23 決定）。** 數值：`--surface` 上 2.48:1、`--bg` 上 2.38:1。這是明講的取捨，不是漏算：

- 前一版用 `sand-500`（3.53:1，唯一過得了門檻又不會深到像已選取的淺色階）
- 改用 `sand-400` 是為了**較輕的視覺重量**：未選取的輪廓是「還沒填」的狀態，不該跟已選取的實心圖示搶注意力。代價是低視力使用者、強光下比較難看出未選取的輪廓
- **之後不要當成缺陷改回 3:1。** 要改，先推翻這一段的理由
- **但也不要再往下退回 `--border`**（`tests/unit/icon-stroke.test.mjs` 會擋）：1.23:1 是真的看不見，那是另一回事

**`--control-empty` 也不是 §4.10 的「未標記按鈕」。** 那種按鈕裡面有文字，文字自己說明了它可以按，框線只是形狀，所以維持 `--border`。這裡沒有文字，輪廓就是全部的資訊。

**開關（`ToggleSwitch`）也不適用 `--control-empty`，關閉的軌道維持 `--border`**（2026-09-23 決定）。開關尺寸大，靠圓鈕與軌道的形狀就能辨識是可操作的控制項，不必靠輪廓的深淺；關閉狀態用深色，反而讓預設狀態顯得突兀。`tests/unit/icon-stroke.test.mjs` 的反掃排除開關，並確認它維持 `--border`。

**烘焙度另成一組獨立色階**（`--roast-light` 到 `--roast-dark`，各配一個經對比驗算的文字色）。它表達的是被記錄的事物本身而非介面狀態，因此不併入上面三組。用於無豆袋照片時的卡片填充，色塊上會疊豆名。

### 2.3 尺寸與其他

| Token | 值 | 用途 |
|---|---|---|
| `--radius-sm` | `4px` | 輸入框、按鈕、標籤、徽章 |
| `--radius-md` | `8px` | 卡片、表單區塊 |
| `--radius-lg` | `12px` | 對話框、浮出層 |
| `--touch-min` | `44px` | §7 的觸控目標下限。**是規範數值不是可調間距**，所以有 token |
| `--content-max` | `720px` | 一般頁面寬度上限 |
| `--content-max-narrow` | `26rem` | 登入、註冊這類只有幾個欄位的頁面 |
| `--overlay-shadow` | 見 tokens.css | 唯一一級陰影，僅供浮出層。卡片與表單區塊一律不用陰影，改以邊界或底色差異分層 |
| `--motion-duration` | `175ms` | §6 |
| `--motion-ease` | `cubic-bezier(0.2, 0, 0, 1)` | §6 |

**正圓用 `rounded-full`，不要用 `--radius-lg` 湊。** 切換開關、強度圓點、浮動按鈕都是正圓；靠「12px 剛好等於半徑」在尺寸改變時會靜默失效。

**間距沒有 token**，走 Tailwind 預設刻度——§9 已授權間距數值由實作決定。

### 2.4 字級

五級，基準 16px。上兩段比例 1.33（標題之間要拉得開），下兩段約 1.13。

| Token | 值 | 行高 | 用途 |
|---|---|---|---|
| `--text-2xl` | `2rem`（32px） | 1.3 | 詳情頁主標題（豆名、紀錄標題） |
| `--text-xl` | `1.5rem`（24px） | 1.35 | 頁面標題、錯誤頁標題；**置中對話框的標題**——無襯線（`--font-body`）、字重 400，見 §4.8。全螢幕浮層不適用 |
| `--text-lg` | `1.125rem`（18px） | 1.5 | 區塊標題、全螢幕浮層的標題（器材選擇器） |
| `--text-base` | `1rem`（16px） | 1.75 | 內文、輸入值（body 預設） |
| `--text-sm` | `0.875rem`（14px） | 1.7 | 欄位標籤、次要資訊、輔助說明、分組標題 |

**中文文字不得小於 `0.875rem`（14px）。** 使用者的情境是沖煮當下——站著、手可能是濕的、注意力在水流上、螢幕離眼睛比坐著遠。12px 在那個情境下看不清楚。

原本的第六級 `--text-xs`（12px）併入 `--text-sm`：tokens.css 裡 `--text-xs` 等於 `var(--text-sm)`。**名字保留、不刪**——刪掉的話 `text-xs` 會悄悄回到 Tailwind 內建的 12px，而且不會報錯。現有的 `text-xs` 之後有理由碰那些檔案時順手改成 `text-sm`。

合併之後，「次要」靠顏色表達（`--text-muted`），不再靠字級：欄位標籤與它下方的輔助說明一樣大，前者是 `--text`、後者是 `--text-muted`。

## 3. 版面

### 斷點

| 名稱 | 寬度 | 版面 |
|---|---|---|
| 手機 | < 640px | 單欄，主要設計目標 |
| 平板以上 | ≥ 640px | 單欄置中，最大寬度 720px |

**不做桌機專屬版面。** 這是手機工具，桌機只需要能正常閱讀，不需要多欄或側邊導覽。唯一例外是豆子詳情頁的比較表，在寬螢幕上可以完整展開不捲動。

### 導覽

#### 三種畫面，各有自己的導覽

以前頂部角落同時放過四種性質不同的東西：導覽（回首頁、設定）、頁面動作（編輯）、流程進出（取消），外觀一模一樣。按「取消」可能丟掉資料，按「回首頁」不會，使用者無法從位置判斷按下去會發生什麼。所以先把畫面分類，每一類只有一套規則：

| 類型 | 有哪些 | 頂部 | 分頁列 | 右下新增 |
|---|---|---|---|---|
| **瀏覽型** | 首頁、豆子列表、器材列表 | 只有頁面標題。首頁右上角多一個齒輪 → `/settings` | 有 | 有 |
| **檢視型** | 豆子詳情、紀錄詳情、設定 | 左上 ‹ **返回**（豆子詳情、設定是上一層；紀錄詳情是上一頁）；右側空著 | 有 | 沒有 |
| **流程型** | 所有表單（紀錄、豆子、器材的新增與編輯）、器材選擇器、裁切介面 | 左上 ‹ **離開**（暫存保留）；右側空著 | 沒有 | 沒有 |
| **分享頁** | `/s/[code]`（《02》§7.2） | 沒有 ‹，只有一行產品名 | **已登入才有** | 沒有 |

- **瀏覽型**：使用者在裡面移動，隨時可能跳去別的區域。出口是分頁列，所以**不放「回首頁」**——重複的入口只是冗餘。
- **檢視型**：看一個特定的東西。檢視不是流程，使用者隨時可能想跳走，所以分頁列保留。**編輯與刪除在內容區**（主要按鈕之後，編輯有框、刪除無框），不在頂部角落。
- **流程型**：在完成一件事，中途離開會丟東西。底部是儲存按鈕，分頁列會搶掉它的位置，所以不顯示。

登入與註冊不屬於前三種的任何一種：還沒進到產品裡，沒有分頁列，也沒有上一層。

**分享頁是第四種，因為它的觀眾不一定是使用者。** 未登入的人看到分頁列只會被帶到登入頁——那是一個他沒有要求的要求；已登入的人看到分頁列則是對的，他確實可以從這裡回到自己的東西。所以分頁列由**登入狀態**決定，不由頁面類型決定，這是全站唯一這樣的頁面。
兩種身分都沒有 ‹：對朋友來說這一頁沒有上一層，也沒有他來的地方（他是從 LINE 點進來的）。

**頂部右側原則上是空的**，唯一的例外是首頁的設定齒輪。

**分享圖示不放在頂部**，它在紀錄詳情頁的**內容標題列**（豆名那一行）最右端。理由與編輯、刪除放在內容區一樣：那是這一頁的頁面動作，不是導覽。頂部只放導覽，是使用者判斷「按下去會不會離開這一頁」的唯一線索。

#### 分頁列

底部固定，三項：首頁、豆子、器材。設定不是分頁，是首頁右上角的齒輪（設定內容變多之後再考慮「帳戶」分頁）。

**顯示規則：瀏覽型與檢視型顯示，流程型不顯示。** 每一頁用 `definePageMeta({ screen })` 宣告自己是哪一種，分頁列由 `app.vue` 依這個宣告統一放，頁面不自己放。新頁面沒有宣告類型時測試會擋（`tests/unit/navigation-wiring.test.mjs`）。這條規則以前只存在於元件註解裡，各頁自己決定放不放。

**亮哪一項**：豆子詳情亮「豆子」（它的列表頁在那裡）；紀錄詳情亮「首頁」（紀錄沒有自己的列表頁，它出現在首頁時間軸）；設定亮「首頁」（從首頁的齒輪進去）。

#### 返回：有父層列表頁才用階層式，沒有就用歷史式

**判斷依據：階層式返回只在該內容真的有父層列表頁時使用。** 沒有父層的內容用歷史式（回上一頁），沒有上一頁時 fallback 到它實際出現的地方。

| 頁面 | ‹ 返回到 | 方式 |
|---|---|---|
| 豆子詳情 | 豆子列表（`/beans`） | 階層式：豆子有列表頁，那個父層是真的 |
| 設定 | 首頁（`/`） | 階層式：只從首頁的齒輪進來 |
| 紀錄詳情 | 上一頁；沒有上一頁時回首頁 | 歷史式 |

**紀錄詳情為什麼不是階層式。** 這裡曾經定成「回到那筆紀錄的豆子」，前提是「紀錄屬於豆子」。但資料模型不是這樣——`brews` 是唯一的主體，豆子是它的一個維度，這在專案最早期就定案了。導覽用了一種詮釋，資料用了另一種。使用者從首頁時間軸點進紀錄，那裡把紀錄列成獨立的東西，所以他不認為紀錄屬於豆子；按 ‹ 卻到了豆子詳情，一個他沒去過的地方。

真正的問題是**紀錄沒有自己的列表頁**——它只存在於首頁時間軸與豆子的比較表裡，所以在導覽上沒有父層，任何階層式的答案都是猜的。在這個結構問題解決之前（CLAUDE.md 的 V2 待辦：紀錄的獨立列表頁），歷史式是誠實的：指向使用者實際來的地方，而不是指向一個他不認同的父層。

**代價**：歷史式的 ‹ 與瀏覽器返回鍵做一樣的事。這是接受的——重複只是冗餘，指向錯的地方是誤導。

「上一頁」是路由器記在 `history.state` 裡的上一筆。**重新整理不會清掉它**，所以重新整理之後 ‹ 仍然回到使用者實際來的地方；只有從外部連結直接打開（沒有上一頁）才走 fallback。

流程型的 ‹ 離開到哪裡，同樣只看網址：

| 頁面 | ‹ 離開到 |
|---|---|
| 新增紀錄 | `?copy={id}` → 來源紀錄；`?bean={id}` → 那支豆子；都沒有 → 首頁 |
| 編輯紀錄 | 那筆紀錄 |
| 新增豆子 | 豆子列表 |
| 編輯豆子 | 那支豆子 |
| 新增器材、編輯器材 | 器材列表 |

編輯頁找不到那一筆時，‹ 回上一層的列表（紀錄是首頁）——回到它的詳情頁只會再看到一次「找不到」。

#### 離開流程時，表單頁不留在 history 裡

儲存之後、刪除之後、按流程型的 ‹ 離開時，都照同一條規則走：

- **上一頁就是目的地**：退回去。詳情 → 編輯 → 儲存，回到原本那一筆詳情，不會多出一筆一樣的
- **其他情況**：取代目前這一頁（`replace`）。新增 → 儲存，表單那一筆換成新紀錄的詳情

用 push 的話，儲存後按返回會回到表單，刪除後按返回會看到「找不到」。只用 replace 也不夠：詳情 → 編輯 → 儲存會留下兩筆一樣的詳情，按 ‹ 或返回鍵看起來沒有反應。

| 動作 | 目的地 |
|---|---|
| 儲存紀錄、豆子 | 那一筆的詳情 |
| 儲存器材 | 器材列表 |
| 刪除紀錄 | 首頁 |
| 刪除豆子 | 豆子列表 |
| 刪除器材 | 器材列表 |

實作見 `composables/useFlowExit.ts`。

#### 取消與離開

同一個「取消」曾經在三個地方做三件事：表單頁右上角（其實保留暫存）、器材表單（真的丟棄）、就地新增（清空輸入）。現在拆開：

- **會丟東西的動作，用「取消」文字。** 就地新增的取消（清空填到一半的內容）、裁切介面的取消（不保留剛選的這張）、刪除確認的取消（不刪）
- **不丟東西的，用 ‹ 圖示。** 流程型的 ‹ 叫「離開」：暫存留著，回來還在。檢視型的 ‹ 叫「返回」

器材選擇器的清單畫面沒有「取消」：不選就離開是標題列的 ‹，兩個做完全一樣的事的按鈕只會讓人猜哪一個會丟東西。新增畫面的「取消」會清掉填到一半的內容，與 ‹（保留）不同，所以留著。

用詞的定義見《04》的「九、導覽與動作」。

#### 浮層與返回鍵

浮層不是路由。手機使用者的第一反應是按返回，所以**浮層開啟時佔一筆 history，返回鍵關掉浮層而不是離開頁面**。

- 返回鍵一次只關最上面那一層（器材選擇器的新增畫面算疊在清單上的第二層）
- 「取消」、點外面、Esc 關閉時，把那一筆退掉——不能留下多餘的紀錄，否則之後要按兩次返回才離開
- 浮層還開著就要導向別頁（例如確認刪除之後導回列表）時，先退掉浮層那一筆、等退完才導覽

適用：器材選擇器、裁切介面、下拉浮層、刪除確認對話框。

**例外：暫存詢問（「上次的內容尚未儲存」）不佔 history。** 它一定要回答；返回鍵若只是關掉它，表單會停在「沒接著填、也沒重新開始」的狀態。按返回就照原本離開這一頁，暫存留著，下次進來再問一次。

實作見 `utils/overlayHistory.ts`。

## 4. 元件規範

### 4.0 變動頻率決定視覺權重

**一個東西多常被改動，決定它值得佔多少視覺權重。** 這條同時管兩件事：

**一、欄位的 L1／L2 判斷。** 每次都會填的欄位放 L1（永遠可見），偶爾才填的放 L2（收合區）。判準不是「重不重要」而是「多常填」——豆名很重要但也很常填，兩者剛好一致；官方風味描述同樣重要，卻是買到才抄一次，所以進 L2。

**二、控制項的呈現形式。** 低頻的狀態切換用**標籤 ＋ 編輯頁**，不用常駐的 toggle：

| 變動頻率 | 呈現 |
|---|---|
| 每次使用都可能改 | 常駐控制項（toggle、選擇器）直接放在該物件旁邊 |
| 偶爾改（數週以上） | 列表上只顯示狀態標籤，要改進編輯頁 |

**實例：器材的「常用」。** 一台磨豆機設成常用之後幾乎不會再換。列表卡片上因此只顯示一個不可點的「常用」標籤，要改得進編輯頁。原本那裡是 toggle，有三個問題：

1. 它的視覺權重與卡片本身接近，看起來像卡片裡還有一張卡片，而它只是一個布林值
2. 切換要打資料庫再重載清單，中間必然閃一次載入狀態；標籤化之後列表頁完全唯讀，沒有這個卡頓
3. toggle 的語意不精確（見下一段）

代價是改常用多一次點擊。低頻操作可以接受；**高頻操作不可以，不要把這條套到每次沖煮都要選的欄位上。**

**三、欄位要不要出現。** 欄位的存在本身就是一種指令——使用者看到空欄位，會覺得自己應該填。不確定是否該收錄的欄位，**預設不顯示並提供開啟入口**，比「顯示但不必填」誠實。「選填」兩個字擋不住義務感，而義務感產出的是憑回想湊出來的數字。

**入口不是欄位。** 「提供入口」與「提供欄位」是不同的事：空的輸入框在說「這裡該填東西」，一個連結在說「這裡有個功能，你可以用」。後者不產生義務感，因為它不是待完成的任務。所以「預設不顯示欄位」與「在欄位原本的位置放一個開啟入口」並不衝突——反而是配套：沒有入口的話，需要那個欄位的人根本不知道它存在。

**實例：分段時間。** 沒有記錄時間習慣的人看到「停 ___ 秒」，會試著回想一個數字填進去；那種資料沒有價值，還會污染比較表——以為在比較兩次沖煮，其實在比較兩次回想。會刻意調整停水時間的進階使用者則確實需要它。所以時間欄位預設不顯示，由分段注水區標題列的切換入口開啟（《02》§5 區塊三）。這是使用者對自己的宣告，不是系統替他分級——與 §4.2「用行為推斷，不用問卷詢問」不衝突：收合區是在猜頻率，這個開關問的是「你要不要記這項」，只有使用者自己知道。

**用詞也照使用者的說法。** 這個欄位在資料庫是 `is_default`，但介面一律說「常用」——使用者的說法是「我常用的那台」，而且「常用」說得通它的功能因果：**因為你平常用這台，所以新增紀錄時幫你先填好**。「預設」說不通這個因果，它是系統視角的詞。資料庫欄位名不必跟著改，那是兩個層次。

### 4.0.1 單選狀態不要用 toggle

**低頻的單選狀態切換用「動作按鈕」，不用 toggle。**

toggle 表達的是**獨立的開關**：使用者看到三台磨豆機各有一個 toggle，會以為三台可以各自開關。但同類型只能有一台常用（資料庫有 partial unique index），開了 A 就會關掉 B——**而那個副作用不在畫面上**。

單選有兩種正確做法，依選項是否同時可見而定：

| 情況 | 做法 |
|---|---|
| 所有選項同時可見（同一個清單裡） | radio |
| 選項分散在不同頁面或畫面 | 動作按鈕 ＋ **事後回饋** |

器材屬於後者：編輯頁一次只看得到一台。所以用兩個狀態的按鈕（`設為常用` ／ `取消常用`）。

**副作用寫在動作之後，不是動作之前。** 按下之後回饋：

> 已將 Comandante C40 設為常用

**不要在按下之前警告「目前常用的是 X，設定後會換成這台」。** 使用者按「設為常用」時意圖已經很明確，事前提醒他會換掉哪一台，是把系統的顧慮丟給他判斷——與《02-功能規格》§10 的那條通則（任何「提示確認」「你是不是」類型的互動，都要先問這個介面是在幫使用者還是在幫系統）是同一件事。事前只說明功能因果就好：

> 新增紀錄時會自動填入

**回饋只在使用者真的按下時出現。** 本來就是常用的那台一打開表單就是開啟狀態，那是「原本就是這樣」不是「剛剛做了什麼」，不該冒出一句回饋。

**允許取消，不要阻止。** 沒有任何常用是合法狀態——新使用者本來就沒有，表單欄位留空一切正常。

**不可復原的動作同樣依這條降級。** 器材的「刪除」從列表卡片收進編輯頁：它比「編輯」低頻得多，兩者並列時視覺權重不對等，而且列表上一排刪除按鈕是誤觸來源。


### 4.1 表單輸入

**數值輸入必須使用數字鍵盤**：`inputmode="decimal"`，並移除 `type="number"` 的上下箭頭（在手機上是誤觸來源）。

**單位顯示在輸入框內右側**，不用 placeholder 表達單位。placeholder 只用於範例值。

**即時衍生值顯示在輸入框下方**，以次要文字呈現。例如粉重下方顯示「1:15.0」，分段區下方顯示「總水量 250g」。

**不得使用浮動標籤（floating label）。** 標籤固定在輸入框上方。資料密集的表單需要標籤持續可見。

**錯誤訊息**只在送出時顯示，不在輸入過程中即時跳出。訊息說明怎麼修正，不只說明錯了。

**表單欄位下方的說明與提示文字分三層，顏色不得混用。** 這條只管這個位置的文字，不是全站通則。

| 層 | 什麼時候出現 | 顏色 | 例子 |
|---|---|---|---|
| 錯誤 | 擋住儲存 | `--danger` | 「請填粉重」、存檔失敗的訊息 |
| 提示 | 針對使用者這次填的值出現，但不阻擋儲存 | `--notice` | 「超出磨豆機刻度範圍」、「不符最小間隔」、「填寫磅秤顯示的累積水量」、「粉水比偏低，請確認悶蒸水量是否合理」 |
| 參考資訊 | 不隨輸入改變，一直都在 | `--text-muted` | 「刻度 1–8　最小間隔 0.5」、「至少 6 個字元」、型錄備註 |

**為什麼提示要與參考資訊分開**：參考資訊一直都在，使用者看久了會自動略過它——這是正常且必要的，欄位說明本來就不該每次都讀。但針對輸入出現的提示必須在出現的當下被注意到，混在同一個灰色裡等於不存在。

**為什麼提示不能用紅色**：紅色在這個產品裡只代表一件事——這樣送不出去。把提示染紅的代價是使用者以為存不起來，於是去改一個其實正確的數字。研磨刻度超出型錄範圍就是這種提示：型錄可能有誤、機器可能改裝，那個數字很可能是對的（《02》§5、《01》§3.2）。

`--notice` 取 `--sand-700`（`#67521f`）：對 `--surface` 7.49:1、對 `--bg` 7.20:1、對 `--accent-wash` 5.45:1。刻意比 `--text-muted`（5.15:1）更深——同一行裡它要比旁邊的參考資訊重，而不是一樣重。

**提示與參考資訊同一行時**，提示接在參考資訊後面，不另起一行：另起一行會讓它看起來就是另一條參考資訊。中文預設可在任兩個字之間換行，所以提示要整段不斷行（`white-space: nowrap`），一行放不下時整段換到下一行。

提示不夠醒目時，先問「該出現的提示有沒有真的出現」，再考慮加重視覺。

### 4.2 收合區（L2）

標題列可點擊展開，右側有方向指示。

**展開狀態需記憶**：使用者展開過一次，之後預設展開，存於 `localStorage`。這是本產品唯一的使用者分級機制——用行為推斷，不用問卷詢問。

收合區的標題文案要說明裡面有什麼，不要只寫「更多設定」。例如「其他器材與環境」。

### 4.3 五點強度選擇器

四行（酸質、甜感、醇厚、苦味），每行五個可點擊的圓點。

- 一次點擊完成選擇，不使用滑桿或下拉
- 觸控目標至少 44×44px（圓點視覺可以小，可點區域要夠大）
- 未選取狀態要明顯是「可以不填」，不是「還沒填完」——不使用紅色、驚嘆號或任何催促性的視覺。
  但**輪廓本身要看得見**：空心圓點用 `--control-empty`（§2.2，`sand-400`），不用 `--border`。
  「可以不填」與「看不出那裡有東西可以按」是兩回事
- 已選取時，被選中的點與其左側的點一併填實（表達強度累進），或僅填實被選中的點——擇一，全站一致
- 「弱／強」只標一次，放在四列圓點的上方、與圓點欄的兩端對齊，不用數字。不逐列標示：四列意思相同，而且逐列標示在 375px 下放不進卡片（右端的「強」會被切掉）

**文案不得出現「評分」「分數」「幾分」。** 使用「強度」。這四個維度描述的是強弱，不是好壞。

### 4.4 分段注水編輯器

所有段落在同一份清單、同一套卡片外觀裡。`step_type` 為 `bloom` 的那一段標題顯示「悶蒸」、不可刪除、不可標攪拌，其餘與一般段落相同——不另用底色或分隔，兩種卡片樣式並存會讓同一份清單看起來像兩種東西。沒有悶蒸的分段（四六法）第一段就是「第 1 段」（《02》§5 區塊三）。

每一段兩個輸入格：「注到」`[___] g` 與「停留」`[___] 秒`，標籤在輸入框上方（§4.1）。

**時間欄位預設不顯示**，由分段注水區標題列的切換入口開啟（§4.0 第三點）。不顯示時每段只有 `注到 [___] g`，兩欄格線保留，水量輸入框寬度不變。

時間欄位的標籤是「停留」（咖啡圈的通用說法，不改），填的是**停水時間**。第一段的停留欄位下方有一行輔助說明「停水時間」，`--text-muted`，與其他輔助文字同級。只寫在第一段：每段意思相同，逐列重複是雜訊。

**切換入口在分段區的標題列右側**，文字連結，不是 toggle：

| 目前狀態 | 連結文字 |
|---|---|
| 關閉 | 記錄停水時間 |
| 開啟 | 不記停水時間 |

點擊即時切換，時間欄位跟著出現或消失，寫入的是**全域偏好**（`profiles.record_step_times`），影響之後所有紀錄。**這是唯一的入口**，設定頁沒有第二個控制點。開啟之後在分段區下方回饋一行「之後的紀錄都會有時間欄位」（`--text-muted`），只在該次切換後顯示，重新進入表單不再出現。

**為什麼不用 toggle。** 表單裡已經有 toggle 的先例（豆子的「已喝完」），那是「這筆資料的一個欄位」。分段區再放一個 toggle，使用者會解讀成「這筆紀錄要不要記時間」，但它其實會影響之後所有紀錄——同一個控制項在同一個表單裡代表兩種性質，是語意混淆。而且依 §4.0，這個開關一旦決定幾乎不會再動，不該佔常駐控制項的視覺重量。

文字連結的缺陷是它看起來像一次性動作、實際會被記住，所以要有那行回饋。與器材「常用」同構：副作用在動作之後回饋，不在動作之前警告（§4.0.1）。

**最後一段不顯示這個欄位**（《02》§5 區塊三）：最後一注之後沒有下一注，沒有「停水」這件事。不反推、不計算、不顯示。

排列成兩欄的緊湊列表，每列有刪除鈕。列表下方「新增一段」。

**段落之間顯示計算出的增量水量**（次要文字，例如「+70g」），幫助使用者確認自己填對了。

分段區下方顯示總水量與粉水比。

### 4.5 豆子卡片

豆子有兩種呈現，版面不同，規則也不同。

**豆袋照片一律放在正方形容器裡**：首頁卡片、豆子列表縮圖、豆子詳情、豆子表單與就地新增的預覽。裁切框是正方形，使用者在裁切畫面框選的區域就是每一處看到的區域——不會被容器再裁一次，也不會有黑邊。`object-cover` 只為了裁切功能上線前存的非正方形舊照片而保留。

#### 4.5.1 首頁上區的橫向卡片列

橫向捲動，卡片等寬等高。照片區為 160×160 的正方形。

有豆袋照片時照片為主視覺；無照片時以烘焙度色塊填充，疊上豆名。**兩者高度必須相同。**

**「等高」這條只適用於這裡。** 橫向排列時高度不一致會直接破版，這是版面限制而非美學偏好。

卡片上的資訊：豆名、養豆天數、沖煮次數、愛心次數。

養豆天數是這張卡片上最有價值的資訊（它會變化，而且影響風味），視覺權重應高於其他數值。

#### 4.5.2 豆子列表頁的單欄列項

**橫式，不是直式大圖。** 左側 96px 見方的縮圖，右側資訊。

直式大圖在單欄列表上每一項都太高，一個畫面看不到幾支豆子；無照片時整塊色塊佔滿寬度也顯得空。

- 左側：照片以 96×96 裁切；無照片時用烘焙度色塊填同樣尺寸
- 右側三行：豆名、咖啡店名、養豆天數。沒填的那行整行不顯示
  - **咖啡店名**：台灣的豆袋上，店名往往是最顯眼的元素，使用者靠它認出這支豆子
  - **不放沖煮次數**：大多數時候是 0，佔一整行卻沒有資訊價值；放在豆子詳情頁
  - **不放烘焙度**：沒有照片時縮圖的色塊已經表達了烘焙度

單欄排列時高度天然一致，**不適用 4.5.1 的等高規則**。

### 4.6 比較表（豆子詳情頁）

這是本產品最重要的單一元件，也是對 Excel 使用者的核心差異化。

- 橫向可捲動，**第一欄（日期）固定不動**
- 數字等寬對齊（tabular-nums）
- 有愛心的列以底色標示，愛心圖示顯示在最右欄
- **與前一列不同的數值加上視覺標記**（字重或顏色），這是讓使用者看見調整軌跡的關鍵
- 依時間由舊到新排序，讓演變方向由上而下
- 點擊任一列進入該筆紀錄。**日期做成連結樣式**（`--accent`、底線）作為可點的線索；其他格維持原本顏色，但仍可點。不用 chevron，也不用底色（底色已表達收藏）或 hover（手機沒有 hover）
- 欄位標題：`養豆`、`粉重`、`粉水比`、`水溫`、`刻度`、`沖煮時間`。空間不夠才用簡稱，見《04-詞彙表》

**手機上的可用性是驗收重點。** 表格在手機上容易做壞，需要實際在 375px 寬度下測試捲動與可讀性。

### 4.7 差異區塊（紀錄詳情頁）

```
相對上一次
研磨刻度   22 → 20
水溫       92 → 90°C
```

箭頭使用 `→`（此處是資料的一部分，不是裝飾，不受第 1 節的箭頭禁令限制）。

前後值的視覺權重不同：舊值次要，新值主要。

### 4.8 對話框

刪除確認使用自訂對話框（`ConfirmDialog`）。

**標題是陳述句，說明刪除的是什麼，不加問號**（2026-09-24 決定）：

| 對象 | 標題 |
|---|---|
| 豆子 | 刪除「豆名」，例如：刪除「衣索比亞 西達摩」 |
| 器材 | 刪除「器材名稱」，名稱沿用畫面上既有的顯示方式（型錄是「品牌 · 型號 版本」，自建是自建名稱），例如：刪除「Comandante · C40 MK4」 |
| 沖煮紀錄 | 刪除這筆紀錄（紀錄沒有名稱） |

**名稱加「」**：豆名常有空格，不加引號時看不出動詞和名稱的界線（「刪除衣索比亞 西達摩」）。名稱很長時照 `text-balance` 換行。

**內文用陳述句，句型統一**（§5.5）：第一句一律是「刪除後無法復原。」；有連帶影響時，第二句說明，不用「只是」「沒辦法」「就好」這類口語。

| 對象 | 內文 |
|---|---|
| 沖煮紀錄 | 刪除後無法復原。分段會一併刪除，豆子會保留。 |
| 豆子（沒有沖煮紀錄） | 刪除後無法復原。 |
| 豆子（有沖煮紀錄） | 刪除後無法復原。這支豆子的 N 筆沖煮紀錄會一併刪除。——外鍵是 cascade，這一句不能省 |
| 器材 | 刪除後無法復原。相關沖煮紀錄會保留，但不再顯示這個器材。 |

**確認按鈕寫「刪除」**，不寫「確定」，也不重複對象（2026-09-23 決定）：標題已經說明刪除的是什麼，按鈕再寫一次「這筆紀錄」不多資訊。

**開啟時焦點放在標題**（`tabindex="-1"`），不落在任何按鈕上，所有置中對話框都一樣（`ConfirmDialog`、`DraftOverlay`、分享對話框）。`showModal()` 預設會聚焦第一個按鈕，觸控使用者因此一打開就看到焦點框；而焦點不在刪除按鈕上，按 Enter 也不會誤刪。焦點框只在鍵盤操作時出現（`:focus-visible`）。

**頁面上的按鈕同樣不重述畫面上已有的脈絡。** 豆子詳情頁上只有一支豆子，刪除鍵寫「刪除」就夠了，「刪除這支豆子」的後四個字不承載資訊。同理，狀態切換寫「已喝完」而不是「標成已喝完」。

#### 置中對話框的標題：無襯線、`--text-xl`、字重 400（2026-09-23 決定）

**置中對話框的標題**一律用無襯線（`--font-body`）、`--text-xl`（24px）、字重 400。目前適用：

| 元件 | 標題 |
|---|---|
| `ConfirmDialog` | 刪除「豆名」／刪除「器材名稱」／刪除這筆紀錄 |
| `DraftOverlay` | 上次的內容尚未儲存 |
| `BrewShare` | 分享紀錄 |

**理由：對話框是操作層，頁面標題是內容層，用字型區分兩者。** 頁面標題說的是「你在看什麼」（這支豆子、這筆紀錄），是內容的一部分；對話框標題說的是「現在要你決定什麼」，是疊在內容上的一次操作。

**依所在的容器決定，不依字級決定。** 頁面裡的 h1、h2（頁面標題、詳情頁主標題、區塊標題）維持襯線（`--font-heading`）、字重 700；只有置中對話框的標題用無襯線。所以同樣是 24px，頁面標題是襯線、對話框標題是無襯線——**這是刻意的，不是不一致**，不要把其中一邊改成另一邊。

**全螢幕浮層不適用。** 器材選擇器（`EquipmentPicker`）鋪滿整個畫面、有自己的 ‹ 與標題列，使用者在它裡面瀏覽與新增，它扮演的是一個頁面——標題維持襯線、`--text-lg`、700。裁切照片（`PhotoCropper`）沒有標題。

**標題改成字重 400 之後，對話框主體不能比它重。** 分享對話框的豆名因此也是 400（原本 500 會顯得比標題還重）。主體的層級靠字級與顏色（`--text-muted`）拉開，不靠字重。

**斷行**：

- 對話框標題加 `text-wrap: balance`（`text-balance`）：兩行時兩行長度接近，不會第一行滿、第二行只剩兩三個字
- 對話框標題再加 `word-break: keep-all`（`break-keep`）與 `overflow-wrap: anywhere`（`wrap-anywhere`）：平常只在空格與標點斷行，不從詞中間斷開（`balance` 本身不認得中文的詞）；整串沒有空格、一行放不下時，才允許從中間斷開，不會撐出框外
- 對話框內文加 `text-wrap: pretty`（`text-pretty`）：避免最後一個字單獨落到下一行
- 兩者都是漸進增強：不支援的瀏覽器照一般規則斷行，不會壞

下拉浮層與頁面層級的提示沒有標題，不在這條規則的範圍。`tests/unit/dialog-title.test.mjs` 擋住置中對話框的標題回到襯線、擋住頁面標題被一起改掉，也確認器材選擇器維持襯線。

### 4.9 空狀態

每個列表都需要空狀態，且**空狀態是邀請行動的時機**：

- 首頁（完全無資料）：說明第一步做什麼，主要按鈕導向新增
- 豆子列表：同上
- 豆子詳情的比較表（只有一筆紀錄）：說明再記一筆就能開始比較
- 器材列表：說明設定常用器材可以省下之後的輸入

文案不得只寫「目前沒有資料」。

### 4.10 狀態表現

**所有狀態切換必須同時有文案與視覺變化，不得只改文字。** 適用於已喝完、愛心、預設器材，以及之後任何「開／關」性質的控制項。

只換文字的問題在於：使用者按下去之後，畫面上唯一改變的是一行字，看起來像沒反應。狀態是持續存在的事實，需要一直看得出來，不能只在切換的瞬間用文案交代。

| 狀態 | 表現 |
|---|---|
| 未標記（可點擊標記） | 一般次要按鈕外觀：`--border` 框線、`--surface` 底色 |
| 已標記（目前狀態） | 填實或改變底色：`--accent` 框線、`--accent-wash` 底色、`--accent` 文字 |

**文案在兩種狀態下相同**，描述的是那個狀態本身（「已喝完」），不是動作（不寫「標成已喝完」／「標成還在喝」）。差別由視覺承擔。

**色彩不得作為唯一的資訊載體**（見第 2 節）。因此除了底色，框線與文字顏色要一起變，愛心這類還需要形狀差異（實心／空心）。

互動元素需標註 `aria-pressed`，讓輔助技術讀得到目前狀態。

列表或卡片上的狀態標記（例如卡片角落的「已喝完」）同樣要有視覺，不能只是一行灰字。

### 4.11 暫存狀態指示

**問題**：自動暫存（《02》§6）本身沒錯，但使用者從來不知道系統在幫他存。下次打開看到還原提示，那是一個他不知道存在的東西突然冒出來——狀態指示缺席，還原就變成驚嚇。

**位置：儲存按鈕正下方**，置左。沖煮表單、豆子表單、器材表單（新增、編輯）都有。置左不置中：它是狀態資訊不是主要內容，置中會讓它看起來像一個獨立的區塊。

**不放頂部。** Google 表單把狀態放頂部，是因為它沒有儲存按鈕，狀態是使用者唯一的資料安全訊號。這裡有儲存按鈕，使用者擔心「我填的東西安全嗎」是在**按儲存之前**那一刻，視線在底部；頂部的指示他看不到。

| 狀態 | 圖示 | 文字 | 時機 |
|---|---|---|---|
| 寫入中 | 雙箭頭圍圈（sync） | 暫存中 | 有變動、等待寫入的 500ms 內 |
| 已完成 | 細線打勾 | 已暫存 | 寫入完成後 |

- 持續輸入時每次變動都重新計時，狀態停在「暫存中」，停下來寫完才變「已暫存」。變化是真實的，也不會每打一個字閃一次
- **第一次有內容變動之後才出現**，沒動過的表單不顯示。全部清除、儲存成功之後收起來
- 寫入失敗（私密瀏覽、容量已滿）時收起來，不顯示「已暫存」——沒存進去就不能這樣說
- **不做旋轉動畫**：半秒鐘的旋轉沒人看得清楚（§6）。圖示與文字的切換就夠了
- 圖示 16px、實際線寬 1.5px（§3 的內容區小圖示）。原本是 14px、0.88px，比旁邊文字的筆畫還細
- 打勾用線條，不加實心圓底——那太像完成的慶祝符號
- `--text-sm`、`--text-muted`，不搶儲存按鈕的視覺權重
- 不設 `aria-live`：持續輸入時每停半秒就唸一次，是噪音

**用「暫存」不用「儲存」。** 暫存是這台裝置上的草稿，儲存是按鈕的動作、寫進資料庫。狀態寫「已儲存」會讓使用者以為已經存好了，不必再按（《04》）。

**還原不在這裡。** 狀態指示回答「我填的東西安全嗎」，還原回答「我不要這些內容」——後者的念頭發生在看到內容的當下，也就是打開表單發現裡面有東西那一刻，所以「全部清除」只在頂部的還原橫幅上（《02》§6）。

### 4.12 「範例」標籤

註冊時自動建立的範例資料（《01》§13）在這四個地方顯示一個「範例」標籤：

| 位置 | 擺法 |
|---|---|
| 豆子卡片（列表與首頁橫向卡片） | 與豆名同一行，接在豆名後面 |
| 器材卡片 | 與器材名稱同一行，接在「常用」之後 |
| 紀錄卡片（首頁時間軸） | 與豆名同一行，日期之前 |
| 豆子詳情頁、紀錄詳情頁 | 與頁面標題同一行，接在標題後面 |

**樣式與器材的「常用」標籤完全相同**（§4.0 的「標籤 ＋ 編輯頁」）：`--accent-wash` 底、`--on-accent-wash` 字、`--radius-sm`、`--text-sm`。它們是同一種東西——不可點的狀態標記——所以不另立一套外觀，**不新增顏色**。

**和名稱同一行，不自己佔一行。** 它說的是「這一筆是什麼」，是名稱的修飾語，不是另一個欄位。首頁的橫向卡片寬度固定，標籤出現時由豆名讓位（截斷），不換行撐高卡片——那會讓整列高度不一致（§4.5.1）。

**標籤只說明來源，不改變任何行為。** 範例可以照常編輯、刪除、複製，不加確認、不加提醒、不做「一鍵清除範例」。

### 4.13 分享（圖示、對話框、頁面層級的回饋、分享頁、失效畫面）

流程與規則見《02》§7.1、§7.2。這一節只定版面與文案。**第一版沒有「停止分享」**（《02》§11），這一節的任何地方都不出現它。

#### 4.13.1 紀錄詳情頁的分享圖示

放在**內容標題列**（豆名那一行）的最右端，不在頂部（§3）。

那一行目前是 `items-baseline`——豆名換成兩行時，置中的「範例」標籤會飄在兩行之間，所以對齊基線。**分享圖示不能跟著對齊基線**：它是一個 44×44 的觸控目標，基線對齊會讓整個按鈕往下掉、看起來像掛在標題下面。圖示自己**垂直置中**（`self-center`），標題與標籤維持基線對齊。

- 圖示 22×22、實際線寬 2px（§3 的「頂部導覽與主要動作」那一級）
- 觸控目標 44×44，用負邊距讓圖示本身對齊頁面內距，與 ‹ 同一套做法
- 顏色 `--text`。不用 `--accent`：那是主要行動的顏色，分享不該搶「照這次再沖一次」的視覺權重
- 無障礙名稱「分享」。已經分享過時仍然是「分享」，狀態由分享對話框表達，不寫進名稱
- 長豆名照原本的規則換行，圖示不讓位（`shrink-0`）——44px 是硬性數值（§7），豆名多換一行不是

#### 4.13.2 分享對話框

**按下圖示一律出現**，而且**永遠只有一種樣子**：傳送模型沒有「已分享過」的狀態（《02》§7.1）。

**就是 §4.8 的對話框**，不另做一種新的彈窗、也不做底部面板：原生 `<dialog>` 的 `showModal()`、置中卡片（`max-w-sm`、`p-6`）、`--overlay-scrim` 遮罩、`--radius-lg`、`--surface` 底、`--overlay-shadow`。開啟時佔一筆 history，**點遮罩、Esc、返回鍵都關閉**，並依 §3 的規則退掉那一筆。沒有「取消」或「完成」按鈕。

點遮罩關閉是這個對話框與刪除確認不同的地方：刪除確認一定要明確回答；這個對話框沒有非回答不可的問題，而且加到主畫面後以獨立視窗開啟時沒有瀏覽器的返回鍵。

**結構：標題 → 分享的對象 → 選項 → 動作。**

有照片、有心得、支援系統分享（完整的樣子）：

```
分享紀錄                           ← 浮層標題：無襯線、--text-xl、字重 400（§4.8）
┌─────────────────────┐ ┌──────┐
│衣索比亞 耶加雪菲       │ │ 照片 │  ← 豆名：--text-base、400
│沖煮日期：09/20        │ │96×96 │  ← --text-sm、--text-muted
└─────────────────────┘ └──────┘
選項                               ← 分組標題：--text-sm、400、--text-muted
☐ 分享心得筆記                      ← 勾選框，整列 44px 高
┌────────────┐ ┌────────────┐
│  複製連結   │ │    分享     │     ← 次要在左、主要在右
└────────────┘ └────────────┘
```

其他三種情況只是拿掉一塊，不另外排版：

| 情況 | 差別 |
|---|---|
| 沒有照片 | 右側的縮圖整個不放，**不留空框、不用烘焙度色塊代替**，豆名與日期佔滿整個寬度 |
| 沒有心得筆記 | 「選項」小標與勾選框**整組不出現** |
| 瀏覽器不支援系統分享 | 只有「複製連結」一顆，**滿版、主要按鈕外觀**（`--accent` 底、`--on-accent` 字） |

| 元素 | 文案 | 說明 |
|---|---|---|
| 標題 | 分享紀錄 | 浮層標題（§4.8）。`tabindex="-1"`，開啟時焦點放在這裡 |
| 分享的對象 | 豆名；沖煮日期：MM/DD | **對話框的重點**：確認要送出去的是哪一筆。兩行，不擠成一行中間點分隔（§1）。日期格式與首頁時間軸相同。豆名長的時候換行，不截斷 |
| 照片 | — | 這支豆子的豆袋照片，**96×96 裁切**，與豆子列表的縮圖同一個規格（§4.5.2），`--radius-md`。簽名網址走既有的快取：從首頁或豆子列表進來時已經有了，不另外發請求。替代文字留空——豆名就在旁邊 |
| 小標 | 選項 | 分組標題的樣式：無襯線、`--text-sm`、400、`--text-muted`（`<legend>`） |
| 勾選框 | 分享心得筆記 | **每次打開都預設不勾**。未勾的方框 `--control-empty`，勾選時 `--accent` 底白勾（Lucide `check`）。整列是 `<label>`：點文字也能切換，觸控範圍 44px 高。**不用開關**：這個選項按下按鈕才生效（《02》§7.1） |
| 次要按鈕 | 複製連結 | 外觀與刪除確認的「取消」相同：`--border` 框。只在支援系統分享時是次要按鈕 |
| 主要按鈕 | 分享 | `--accent` 底、`--on-accent` 字。只在支援系統分享時出現 |

**是否支援系統分享依瀏覽器的能力判斷**（`navigator.share` 存在與否），不依桌機或手機判斷。

**不放說明句**（例如「朋友不用登入也能看」）。對話框只回答「送哪一筆、帶不帶心得」。

**焦點**：開啟時把焦點放在標題上，不自動聚焦到勾選框或按鈕。`showModal()` 預設會聚焦第一個可以聚焦的東西，觸控使用者因此一打開就看到一圈焦點框。標題不是互動元素，不畫焦點框；螢幕閱讀器從標題開始讀，鍵盤使用者下一個 Tab 就到勾選框。焦點框只在鍵盤操作時出現（`:focus-visible`，main.css）。

**按下任一顆按鈕之後對話框立刻關閉**，回饋改到頁面層級（§4.13.3）。

#### 4.13.3 頁面層級的回饋

對話框已經關了，這些提示顯示在頁面底部：`position: fixed`，下緣避開分頁列與 iPhone 底部的安全區域（`52px + env(safe-area-inset-bottom)` 再留 12px），寬度與頁面內容相同（`--content-max`、左右 20px）。`--surface` 底、`--overlay-shadow`、`--radius-md`、`--text-sm`。不新增顏色。

| 情況 | 內容 | 收起 |
|---|---|---|
| 複製成功（按「複製連結」，或系統分享失敗改成複製） | 已複製連結 | **約兩秒後自己收起來**。置中的一小塊。`aria-live="polite"`：它不是錯誤 |
| 系統分享與複製都失敗 | 「無法複製，請長按連結手動複製」＋連結本身＋「關閉」 | 按「關閉」。連結是一般文字（`user-select: all`，長按一次選到整串），不做成連結——點下去會離開這一頁 |
| 建立失敗 | 「分享建立失敗，連結目前無法開啟」（`--danger`）＋「關閉」「再試一次」 | **不自動消失**，直到重送成功或按「關閉」。連結已經傳出去了，失敗一定要被看到。`role="alert"` |

系統分享成功時不顯示任何提示：系統選單本身就是回饋。

建立失敗的提示同時只有一則：連續兩次傳送都失敗時，顯示的是最近那一次，「再試一次」重送的也是那一次。

這三種都是**同一件事做完之後的狀態回報**，不是要使用者回答的問題，所以不用對話框；複製成功那一種會自己消失，兩種失敗則要使用者看過才收起。

#### 4.13.4 分享頁（375px）

版面順序與紀錄詳情頁一致，寬度上限同樣是 `--content-max`。由上而下：

```
手沖咖啡紀錄                    ← --text-sm、--text-muted，不是連結
──────────────────────────
（本人才有）你分享的紀錄   前往紀錄
──────────────────────────
衣索比亞 耶加雪菲                ← --text-2xl，豆名
2026/09/20 08:00
★★★★☆  ♥ 收藏
咖啡店名 / 烘焙度 / 烘焙日期     ← 詳情頁沒有的豆子資訊
粉重 / 總水量 / 粉水比 / 水溫 /
研磨刻度 / 沖煮時間 / 養豆天數 /
磨豆機 / 濾杯 / 手沖壺 / 沖煮手法
分段
強度 / 風味
心得（依設定）
```

- **頂部那一行產品名不是連結。** 未登入的人點下去只會被帶到登入頁；已登入的人有分頁列。它的作用只是讓朋友知道自己在看什麼東西
- **沒有 ‹、沒有右下浮動按鈕、沒有任何主要按鈕。** 這一頁唯讀，一個寫入的入口都不放
- **豆子資訊三列排在參數列表的最上面**，與參數同一種 `dl` 列（標籤在左、值在右），不另立一個有標題的區塊，也不擠成一行中間點分隔的 meta（§1）。三項都沒填時整塊不出現
- **心得筆記沒勾時整段不出現**，不留佔位（《02》§7.2）
- **研磨刻度與磨豆機同時出現或同時不出現**，刻度不單獨顯示
- 分頁列：未登入不顯示，已登入顯示，且**不亮任何一項**——這筆紀錄不屬於看的人，亮「首頁」會暗示它在他的首頁上

**本人橫幅**：`--accent-wash` 底、`--on-accent-wash` 字、`--radius-md`，與「範例」標籤同一組顏色（§4.12：同一種「這是什麼」的說明，不另立外觀、不新增顏色）。

- 文案「你分享的紀錄」
- 旁邊只放「前往紀錄」：一般連結，導向 `/brews/[id]`，觸控目標 44px 高
- 字級 `--text-sm`（14px，全站最小的一級，§2.4）。它是附屬的說明，不該比豆名以下的內容更搶眼
- 一行排得下（說明靠左、連結靠右），不必拆成兩行

#### 4.13.5 失效畫面

紀錄已刪除、代碼不存在，兩種情況**同一個畫面**（《02》§7.2）。

版面與 `error.vue` 同一套：`--content-max-narrow`、垂直置中。

```
這筆分享已經無法查看
```

- 標題 `--text-xl`、`font-serif`
- **底下不多寫一行解釋。** 「可能是紀錄被刪掉了」等於把原因說出來，那正是不區分原因要避免的事
- **未登入時不放任何按鈕。** 他沒有可以去的地方，「回首頁」會把他帶到登入頁——那是一個他沒有要求的要求
- **已登入時放一個「回首頁」**，一般次要按鈕外觀

## 5. 文案原則

**每一條都標明適用範圍。** 沒有標範圍的原則會被當成全域語氣指令套到所有地方——例如把「一般語氣」套到空狀態，就會寫出「想到再補就好」這種在跟使用者聊天的句子。範圍以外的地方不適用，不要延伸解釋。

### 5.1 用使用者的語言，不用系統的語言

**適用範圍：全站所有面向使用者的文字。** 欄位標籤、按鈕、提示、錯誤訊息都算。

「注到 160g」不是「累積水量」；「照這次再沖一次」不是「複製紀錄」；「咖啡店名」不是「烘焙商」。

例外：資料庫欄位名、程式碼識別字不受此限，它們不面向使用者。

### 5.2 動詞在整個流程中保持一致

**適用範圍：同一個流程內的按鈕，以及該動作完成後的回饋。**

按鈕寫「儲存」，成功提示就是「已儲存」，不要變成「新增成功」。

不同流程之間不需要統一用詞。

### 5.3 錯誤訊息不道歉，也不含糊

**適用範圍：錯誤訊息與失敗狀態，不含空狀態。**

說明發生什麼事、怎麼處理。空狀態不是錯誤，不適用這條。

### 5.4 不使用驚嘆號，不使用表情符號

**適用範圍：全站，無例外。**

### 5.5 簡潔的陳述句，不用制式敬語，也不用對話口吻

**適用範圍：全站的介面文字——標題、按鈕、對話框內文、提示、錯誤訊息、空狀態、引導文字。**

兩個方向都要避開：

- **制式敬語**：「偵測到未完成的表單，是否要復原？」「您的請求已處理完成」。這是系統在報告自己
- **對話口吻**：「刪掉之後沒辦法復原」「只是那筆紀錄上的器材欄位會變成空的」「直接登入就好」。口語連接詞（只是、就好、其實、先…再）與「沒辦法」「刪掉」這類口語，讓介面像在聊天

介面文字一律用**簡潔的陳述句**：

| 不要 | 要 |
|---|---|
| 偵測到未完成的表單，是否要復原？ | 上次的內容尚未儲存 |
| 刪掉之後沒辦法復原。已經記錄過的沖煮不會消失，只是那筆紀錄上的器材欄位會變成空的。 | 刪除後無法復原。相關沖煮紀錄會保留，但不再顯示這個器材。 |

**標題說明狀況，按鈕說明動作。** 標題不問「要不要…？」，那是按鈕的工作。

**「請」只在有動作要使用者做的時候用**：「關聯的資料已不存在，請重新選擇」有，「電子郵件或密碼錯誤」沒有——後者只是說明狀況，要不要重打由使用者自己判斷。

**例外：錯誤回報的聯絡句可以用溝通語氣。** 錯誤頁與頁內錯誤邊界上那一句「如果一直出現同一組代碼，歡迎來信 …」是開發者直接跟使用者說話，不是介面在報告狀態，保留溝通語氣，不改成制式說法。信箱做成 `mailto` 連結，有錯誤代碼時帶進信件主旨（`utils/errorMessage.ts` 的 `supportMailto`）。

**按鈕、欄位標籤、狀態標記要的是最短的資訊，不是完整句子。** 空狀態尤其不需要安慰或解釋現況——「除了豆名還沒填其他東西，想到再補就好」是在聊天，畫面上本來就看得出沒填，直接不顯示即可。

這條原本寫成「句子使用一般語氣」，沒有標明範圍，結果被套到介面元件上，刪除確認的內文因此寫成了對話。一般語氣的意思只是「不用制式敬語」，不是「像跟人講話」。

### 5.6 空狀態的文案

**適用範圍：所有列表與詳情頁的空狀態。**

空狀態是邀請行動的時機，不是說明現況的時機（見 §4.9）。

- 有下一步可做：只寫那一步怎麼做，不解釋為什麼是空的
- 沒有下一步、或行動入口已經在畫面上：不顯示任何文案
- 一律不寫「目前沒有資料」「還沒有內容」這類複述畫面的句子

## 6. 動態

**只做回應使用者操作的動態**：收合區展開、對話框開啟、切換狀態。時長 150–200ms。

**不做進場動畫。** 頁面載入時的淡入上滑、卡片依序出現、捲動觸發顯示，全部不做。

必須遵守 `prefers-reduced-motion`。

唯一可考慮的例外是愛心切換時的微小回饋，因為它是有情緒意義的操作。

## 7. 可及性

- 所有互動元素可鍵盤操作，focus 狀態明確可見
- 觸控目標至少 44×44px。**適用範圍：按鈕、圖示、可點區塊、表單控制項。** 行內文字連結不適用——把句子中的連結撐到 44px 會破壞行高與段落節奏，這類連結靠上下文與底線辨識即可
- 文字與背景對比至少 4.5:1
- 圖片有替代文字，豆袋照片用豆名
- 表單標籤與輸入框正確關聯

---

## 8. 效能

- 豆袋照片上傳前在前端壓縮（長邊 1600px、品質 0.8、轉 WebP）
- 列表使用分頁或無限捲動，一次不超過 20 筆
- 首頁上區的豆子卡片使用懶載入
- 字體使用 `font-display: swap`

## 9. 實作時可自行決定的部分

以下不需要詢問，實作者依專業判斷處理：

- 具體的間距數值、圓角半徑、陰影參數
- 圖示的選用（建議使用單一套件，不混用多套風格）
- 列表的分頁或無限捲動實作方式
- 載入中的骨架畫面樣式
- Toast 提示的位置與停留時間
- CSS 的組織方式（建議 Tailwind 或 CSS 變數 ＋ scoped style，擇一，不混用）

**以下必須詢問，不得自行決定：**

- 色票的實際數值（第 2 節）
- 新增任何本規格未定義的頁面，或設計系統層級的元件

  「元件」指的是本規格第 4 節那種層級的東西：會被重複使用、有自己的視覺與互動約定、影響全站一致性。內部的組合單元（例如把某個表單拆成 `BeanForm`、`PhotoField`）只是程式碼組織方式，不需要詢問。
- 改動分段注水編輯器的輸入單位
- 改動強度選擇器的維度或級距
- 在第一版加入《02-功能規格》第 11 節排除的任何功能
