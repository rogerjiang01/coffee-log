# 手沖咖啡紀錄平台 — 功能規格

> 搭配《01-資料庫規格》使用。資料結構問題以該文件為準，本文件定義行為。

---

## 0. 給實作者的硬性約束

1. **不得新增本文件未定義的頁面或功能。** 有疑問就停下來詢問。
2. **不得實作第 10 節「明確不做」清單中的任何項目**，即使實作成本很低。
3. **表單自動暫存是必要功能，不是加分項。** 見第 6 節。
4. **必填欄位只有兩個**：豆子的 `name`、沖煮紀錄的 `dose`。不得對其他欄位加上必填驗證。
5. 所有文案使用正體中文，語氣自然口語，不使用「請輸入」「系統提示」這類制式用語。

---

## 1. 產品定位

一個給手沖咖啡愛好者記錄沖煮參數的工具。

**主要使用者**：已經有記錄習慣的人（目前用 Excel、Notion 或紙筆），痛點是記錄太慢、手機上難操作、記了之後難以回頭比較。

**次要使用者**：想開始記錄但不知從何下手的人。透過低門檻的首次流程與內建的手法、風味詞彙接住他們，但不為此犧牲主要使用者的體驗。

**核心價值排序**（決定資源分配的依據）：

1. 記錄成本低到不構成負擔——這是門檻條件，不是價值主張
2. **看得出自己在進步**——這是核心。使用者要能比較同一支豆子的不同版本，看見自己調整的軌跡
3. 參考他人的參數——延伸價值，第一版完全不做

**第一版明確不做社群功能。** 空的按讚數、空的追蹤列表只會向新使用者證明「這裡沒人」，比沒有這些功能更傷。

---

## 2. 使用情境

**情境 A：沖煮後補記（主要，約八成）**
沖完一杯，坐下來，打開 app，記下這次的參數和喝起來如何。大部分情況是「跟上次差不多，改了一兩個地方」。

**情境 B：沖煮前查閱（次要）**
準備沖某支豆子，打開 app 看上次怎麼沖的、哪一次最好喝，記在腦中再去沖。

**不支援的情境：沖煮當下即時記錄。** 這是刻意的取捨。不做計時器、不做逐段即時記錄、不做智慧秤連動。介面不需要為單手濕手操作優化。

由情境 A 的「改了一兩個地方」推導出本產品最重要的一條結論：

> **「複製既有紀錄」的使用頻率高於「從空白新增」。**

所有介面決策都應優先服務複製流程。從空白新增只有在第一次記錄某支豆子時才會發生。

## 4. 首頁

**首頁不是「新增入口」，是「查閱起點」。** 兩種使用情境都是先看既有紀錄，不是從零開始填表。

### 版面結構

上下兩區，不做視角切換。切換器會把決策成本丟給使用者，而兩區並存已經同時滿足兩種需求。

**上區：沖煮中的豆子**

橫向可滑動的卡片列，只顯示 `is_finished = false` 的豆子，依 `created_at` 倒序。實際上通常只有一到三支。

每張卡片顯示：豆袋照片（無照片時見下）、豆名、養豆天數、沖煮次數、愛心次數。點擊進入該豆子的詳情頁。

**有照片與無照片的卡片必須等高。** 無照片時以烘焙度對應的底色色塊填充，上面疊豆名。混合高度會讓整列版面破碎。

若沒有任何未喝完的豆子，整個上區不顯示（不要顯示空狀態文案佔位）。

**下區：沖煮紀錄時間軸**

所有紀錄依 `brewed_at` 倒序，無限捲動或分頁皆可，每頁 20 筆。

每筆顯示：豆名、沖煮日期、粉重與粉水比、水溫、研磨刻度、愛心狀態。若該筆是複製而來且有差異，顯示極簡的差異提示（例如「刻度 22→20」），這是讓使用者一眼看見調整軌跡的地方。

### 全域新增按鈕

固定在畫面右下的浮動按鈕，點擊進入 `/brews/new`。

若目前只有一支未喝完的豆子，直接帶入該豆子（`?bean={id}`），少一步選擇。

## 5. 新增沖煮紀錄

三種進入方式，共用同一個表單元件，差別只在初始值：

| 進入方式 | 路由 | 初始值 |
|---|---|---|
| 從空白新增 | `/brews/new` | 帶入預設器材；豆子欄位空白 |
| 指定豆子新增 | `/brews/new?bean={id}` | 同上 ＋ 豆子已選定 |
| **複製既有紀錄** | `/brews/new?copy={id}` | **複製來源的所有參數與分段**，品飲欄位清空 |

### 複製流程的細節（最高頻路徑，優先做對）

複製時**帶入**：豆子、手法、粉重、水溫、磨豆機、刻度、濾杯、手沖壺、總沖煮時間、完整分段。

複製時**清空**：愛心、心得筆記、強度評分、風味標籤、沖煮照片。品飲是這一次的新體驗，不該繼承。

`copied_from_brew_id` 寫入來源 id。`brewed_at` 設為當下。

理想動線是：使用者從詳情頁點「照這次再沖一次」→ 表單已填好 → 改一兩個數字 → 填品飲 → 儲存。**全程應可在 60 秒內完成。**

### 表單欄位配置

**L1（預設顯示）與 L2（收合在「更多設定」內）** 的判斷原則：不是重要與否，而是**變動頻率**。重要但幾乎不變的欄位（例如濾紙）交給預設值處理，不佔版面。

#### 區塊一：豆子與手法

| 欄位 | 層級 | 行為 |
|---|---|---|
| 豆子 | L1 | 下拉選擇，未喝完的排前面。可直接新增豆子（見下） |
| 沖煮手法 | L1 | 選填。選定後帶入分段模板 |

**豆子欄位必須支援「就地新增」**：選單底部有「新增豆子」，點擊開啟精簡的新增豆子表單（只要豆名 ＋ 可選拍照），儲存後自動選定並回到沖煮表單。**不得跳離頁面導致已填內容遺失。**

**手法帶入分段的邏輯**：使用者選定手法後，依已填的粉重與手法的 `default_ratio` 算出總水量，再依 `step_template` 的比例換算成各段的累積水量與停留秒數，寫入分段區。若粉重尚未填寫，則在粉重填寫後才帶入。

帶入後使用者可自由修改任何數值、增減段數，`brew_method_id` 保持不變。**不得在儲存時檢查分段是否符合模板。**

#### 區塊二：核心參數

| 欄位 | 層級 | 行為 |
|---|---|---|
| 粉重 | L1 | **唯一必填**，數字，單位 g |
| 水溫 | L1 | 數字，單位 °C |
| 磨豆機 | L1 | 帶入預設器材 |
| 研磨刻度 | L1 | 依磨豆機型錄調整輸入範圍與小數支援 |
| 濾杯 | L1 | 帶入預設器材 |
| 手沖壺 | L1 | 帶入預設器材 |
| 總沖煮時間 | L1 | 分:秒 輸入，下壺滴完為準 |
| 沖煮時間 | L1 | 預設當下，可修改 |
| 濾紙 | L2 | |
| 分享壺 | L2 | |
| 水質、水 TDS、室溫、濕度 | L2 | 第一版可全部不露出 |

**研磨刻度的輸入行為**：
- 磨豆機有型錄資料時，依 `grind_scale_min`／`max` 設定輸入範圍，依 `grind_scale_allow_decimal` 決定是否接受小數
- `grind_scale_unit = 'stepless'`（無段機，如 EK43）時，**不做任何範圍驗證，自由輸入**。這類機器的刻度無法跨機比較，但對使用者本人仍有記錄意義
- 自建器材（無型錄資料）時同樣自由輸入

**粉水比即時顯示**：粉重與總水量都有值時，在粉重欄位旁即時顯示「1:15.0」。這是衍生值，不可編輯、不存入資料庫。

#### 區塊三：分段注水

這一區是本產品與競品最主要的差異，必須做得比其他區塊更用心。

**悶蒸單獨呈現在最上方**，兩個輸入格（水量、停留秒數），與其他段落在視覺上分開。資料層仍是 `step_index = 1`、`step_type = 'bloom'` 的一般段落。

**其餘段落以列表呈現**，每列兩個輸入格：

| 顯示 | 輸入 | 儲存 |
|---|---|---|
| 「注到 ___ g」 | 累積水量 | `cumulative_water` 直接存 |
| 「停 ___ 秒」 | 停留秒數 | 換算成 `time_offset` 後存 |

**輸入用停留秒數，儲存用累積時間點。** 使用者的心智是「注到 160g，停 30 秒」，不是「在第 75 秒時」。換算在前端完成：

```
time_offset[1] = 0
time_offset[n] = time_offset[n-1] + 停留秒數[n-1]
```

**累積水量直接輸入，不換算。** 使用者沖煮時看的是磅秤上的累積數字。

每列右側有刪除鈕，列表下方有「新增一段」。段數無上限。

**分段區旁即時顯示總水量**（等於最後一段的累積水量），供使用者確認。這是衍生值，不另設輸入欄位。

段落類型（悶蒸／注水／攪拌／等待）放 L2，預設為「注水」。第一版可只提供切換為「攪拌」的選項。

溫度覆寫、注水手法、段落備註三個欄位第一版不露出。

#### 區塊四：品飲

| 欄位 | 層級 | 行為 |
|---|---|---|
| 愛心 | L1 | 明顯的切換按鈕 |
| 強度評分 | L1 | 四行五點選擇器，見下 |
| 心得筆記 | L1 | 多行文字 |
| 風味標籤 | L2 | 從標籤庫多選，可自建 |
| 出杯重量、飲品 TDS、沖煮照片 | L2 | 第一版可不露出 |

**強度評分必須留在 L1，不得收合。**

四個維度：酸質、甜感、醇厚、苦味。各為 1–5 的五個圓點，直接點選，一次點擊完成。**不使用滑桿**（手機上難精準）、**不使用下拉選單**（需兩次操作）。

四個維度全部可留空，留空不阻擋儲存，不顯示任何提示。

**這四個維度只描述強度，不評價好壞。** 好壞交給愛心與心得筆記。介面文案要避免任何暗示「分數高比較好」的措辭——不使用「評分」「分數」這類字眼，用「強度」。

**風味標籤是給新手的詞彙教學。** 多數人不記錄風味不是因為懶，是因為缺乏描述詞彙。標籤庫應分組顯示（酸質／甜感／口感／風味／缺陷），並使用具體可感的詞（例如「豆漿般的黏稠」而非「body 高」）。

### 儲存後

導向該筆紀錄的詳情頁，不要回首頁。使用者剛記錄完，最可能想確認自己記了什麼。

送出時寫入 `form_duration_seconds`（表單開啟到送出的秒數）。此值不在任何介面顯示。

## 6. 表單自動暫存（必要功能）

**問題背景**：競品 Beanconqueror 的最大缺陷是填到一半按返回會全部消失。這是使用者只會遇到一次、然後再也不回來的錯誤。

**實作要求**：

- 新增與編輯表單的完整狀態即時寫入 `localStorage`，欄位變動時觸發，可 debounce 500ms
- key 格式：`draft:brew:new`、`draft:brew:{id}`、`draft:bean:new`
- 重新進入同一表單時，若偵測到暫存內容，顯示可還原提示：「上次有一筆沒存完，要接著填嗎？」提供「接著填」與「重新開始」兩個選項
- 成功儲存後清除對應的暫存
- 暫存超過 7 天自動失效

**離開頁面前不需攔截確認。** 有自動暫存就不需要用對話框打斷使用者。

## 7. 沖煮紀錄詳情頁

顯示該筆紀錄的全部內容。版面順序建議：豆子與手法 → 核心參數 → 分段 → 品飲 → 差異。

**衍生值在此頁完整顯示**：養豆天數、粉水比、總水量、每段增量水量、每段停留秒數。

### 相對上一版的差異（核心功能）

若 `copied_from_brew_id` 不為空，顯示一個差異區塊，列出相對來源紀錄改動了哪些欄位。

```
相對上一次
研磨刻度  22 → 20
水溫      92 → 90°C
```

**比對範圍**：粉重、水溫、研磨刻度、磨豆機、濾杯、手沖壺、手法、總沖煮時間、分段結構（段數／各段水量／各段時間）。

**這個功能的意義**：使用者不需要多做任何事，只是照原本的動線複製、改數字、儲存，系統就在背後留下他的調整軌跡。累積下來，配合愛心標記，就能看出哪些調整方向是對的。這是本產品「幫助使用者進步」的核心機制。

差異為空（複製後完全沒改）時，不顯示此區塊。來源紀錄已被刪除時（`copied_from_brew_id` 為 null），不顯示。

### 主要行動

**「照這次再沖一次」** 是此頁最主要的按鈕，導向 `/brews/new?copy={id}`。這是本產品最高頻的操作，按鈕權重應高於編輯與刪除。

編輯、刪除放次要位置。刪除需二次確認。

## 8. 豆子詳情頁（核心價值落點）

除了豆子本身的資訊，此頁的重點是**該豆子所有沖煮紀錄的並排比較**。

### 比較表

一個橫向可捲動的表格。每一列是一次沖煮，欄位橫向對齊：

```
日期    養豆  粉重  比例    水溫  刻度  時間   ♥
03/12   12天  15g   1:15.0  92    22    2:30
03/14   14天  15g   1:15.0  92    20    2:20   ♥
03/15   15天  15g   1:16.0  90    20    2:25
```

依 `brewed_at` 排序（舊到新，看得出演變）。有愛心的列以底色標示。

**與前一列不同的數值要有視覺標記**（例如加粗或變色），這是讓使用者一眼看出自己改了什麼的關鍵。

點擊任一列進入該筆紀錄詳情。

**這張表是本產品對 Excel 使用者最實在的差異化。** Excel 在電腦上做得比這好，但在手機上做得極差——而喝咖啡的當下，人都在手機上。因此**這張表必須在手機上好用**：橫向捲動流暢、日期欄固定不動、字級足夠。

### 其他內容

豆袋照片、基本資訊、沖煮次數、愛心次數、養豆天數。

「用這支豆子沖一杯」按鈕，導向 `/brews/new?bean={id}`。

已喝完的切換開關（影響首頁上區顯示）。

## 9. 首次使用流程

**這是整個產品風險最高的一段。** 日常流程可以在 60 秒內完成，但第一次使用要建豆子、建器材、填沖煮、填品飲，若不特別設計會超過五分鐘——比 Excel 還慢。而所有新使用者都從這條路徑進來。

### 設計原則

**每一步都可以跳過。** 使用者應該能在還沒建立任何器材的情況下完成第一筆紀錄。

**豆子只要豆名。** 建豆子表單的必填只有 `name`。其他欄位全部可空，不得加前端必填驗證。

**豆袋照片是逃生路徑。** 在建豆子表單的最上方放拍照／上傳，並以文案說明：拍下豆袋就好，其他之後想填再填。這用極低成本讓不想打字的人也能完成，同時保留了資訊（人眼一秒就能從照片讀出產區處理法）。

**器材可以稍後再設定。** 第一次記錄時器材欄位允許留空。首筆紀錄儲存後，可以提示一次「設定常用器材，之後就會自動帶入」，但不強制、不阻擋。

### 空狀態

首頁在完全沒有資料時，不顯示空的兩區骨架，而是一個明確的行動引導。文案應說明第一步要做什麼，不要只寫「還沒有資料」。

空狀態是邀請行動的時機，不是說明現況的時機。

## 10. 查表型欄位的共通行為

適用於：處理法、品種、產區、風味標籤、沖煮手法。

**顯示規則**：系統內建項目排前面，使用者自建項目排後面，以視覺方式區分兩者。

**自建規則**：選單底部提供「新增」。輸入時對現有項目（含 `aliases`）做模糊比對，命中時提示「你是不是指『厭氧日曬』？」，提供直接選用的選項。

這個比對機制的目的是減少同義異名的重複（「厭氧」「厭氧發酵」「Anaerobic」會變成三筆）。第一版做到提示即可，不需要合併或管理介面。

**自建的項目只有本人看得到**（見資料庫規格第 6.3 節的 RLS policy）。

## 11. 明確不做（V2 待辦）

以下項目已明確排除。**即使實作成本很低，也不得在第一版加入：**

- 社群功能：追蹤、按讚、留言、動態牆、公開瀏覽
- 預期參數與實際參數的雙軌記錄（第一版以自動差異替代）
- 注水手法細節：繞圈方向、繞圈半徑、水柱大小、繞圈速度
- 影片附檔
- 風味雷達圖
- 依熱門度排序的發現機制
- 豆袋 OCR 自動辨識（第一版僅存照片）
- 新手／進階的介面分流
- 沖煮計時器、智慧電子秤連動
- 跨磨豆機的刻度換算
- 資料匯出／匯入
- 第三方登入
- 深色模式（除非實作成本確實接近零）
- 多語系

**注水手法細節特別說明**：這四個欄位在資料表上實作成本不高，很容易讓人覺得順手做一做。但它會讓分段區的每一段從兩個輸入變成六個，直接摧毀「一兩分鐘完成記錄」的目標。結構已預留，介面第一版不做。

## 12. 驗收標準

第一版完成的判斷依據：

1. 新使用者可以在五分鐘內完成註冊到第一筆紀錄，且過程中沒有任何強制步驟
2. 已有一筆紀錄的使用者，可以在 60 秒內透過複製完成第二筆
3. 表單填到一半離開再回來，內容還在
4. 豆子詳情頁的比較表在手機上可正常橫向捲動閱讀
5. 分段注水的輸入是「停留秒數」，資料庫存的是「累積時間點」
6. 無段磨豆機（EK43）可以正常填寫刻度
7. 使用者 A 完全無法讀取使用者 B 的任何資料，包含自建的處理法與手法
8. `form_duration_seconds` 有正確寫入
