# 04 詞彙表

新增或修改任何面向使用者的文案前，先查這份表。

**收錄範圍**：出現在介面文案或規格（《01》《02》《03》）裡的咖啡領域與產品用詞。沒有出現在任何欄位或文案裡的詞不收，這不是咖啡百科。

**第三欄最重要。** 那些同義詞每一個都「也通」，所以最容易被人順手改回去。改回去之後，同一個概念在畫面上有兩種叫法，使用者會以為那是兩件事——這個產品已經因此混淆過一次（「沖煮時間」曾同時指兩件事）。要改用詞，先改這份表，再改介面。

`tests/unit/glossary.test.mjs` 會掃介面文案，第三欄的詞出現就失敗。

## 長短版的使用規則

有些詞有全稱與簡稱：研磨刻度／刻度、沖煮手法／手法、養豆天數／養豆。這不是混亂，是版面限制。

- **欄位標籤與內文用全稱**
- **表格欄位標題空間不夠時才用簡稱**（比較表的「刻度」「養豆」）
- **同一個層級不混用**：同一張表的欄位標題、同一個表單的欄位標籤，要嘛都全稱、要嘛都簡稱

簡稱只能是全稱去掉前綴，不能換成另一個詞。「刻度」可以，「研磨度」不行。

## 一、時間

| 使用的詞 | 精確指什麼 | 刻意不用的同義詞及原因 |
|---|---|---|
| **沖煮日期** | 這一杯是哪一天、幾點沖的（`brews.brewed_at`，含時刻） | **沖煮時間**：這個詞給了 `total_time`，兩件事不能共用一個名字。**紀錄時間／建立時間**：那是資料寫入的時刻（`created_at`），事後補記時兩者不同 |
| **沖煮時間** | 這一杯沖了多久，分:秒（`brews.total_time`）。從哪裡算到哪裡由使用者自己決定，規格不定義 | **總沖煮時間**：以前為了和「沖煮時間」（當時指日期）區分才加「總」，現在沒有「非總」的沖煮時間了。**總時間**：不知道是什麼的總和。**萃取時間**：萃取是咖啡粉接觸水的化學過程，會讓人聯想到萃取率。**時間**（單獨出現）：分不出是沖煮時間還是停水時長；比較表曾經這樣寫，已改掉 |
| **停水時長** | 注完一注到下一注開始之間的秒數，不含注水動作本身（`brew_steps.hold_seconds`、模板的 `duration`）。最後一段沒有下一注，沒有停水時長。分段子頁的欄位標籤、摘要、切換入口（開關「記錄停水時長」；2026-11-17 之前是文字連結「記錄停水時長／不記停水時長」）、差異區都是這個詞（開啟後的回饋「之後的紀錄都會有停水時長」2026-11-17 拿掉了） | **停水時間**：2026-11-16 之前的用語。照 Figma 改成「時長」：它明確指一段時間，「時間」也可能指時間點。**停水秒數／純停水**：同一件事的另外兩種說法，多一個詞就多一個「這兩個是不是不一樣」的疑問。**斷水時間**：「斷水」字面強調把水流切斷的那一下，不是之後等待的那段。**停留／停留秒數／停留時間**：2026-11-16 之前分段的欄位標籤寫「停留」，已經改成「停水時長」。**等待時間**：`step_type` 另有 `wait`，是另一種段落。**時間欄位**：開關回饋的舊寫法（那句回饋後來整句拿掉），「時間」分不出是哪一個時間 |

## 二、水與粉

| 使用的詞 | 精確指什麼 | 刻意不用的同義詞及原因 |
|---|---|---|
| **粉重** | 這一杯用了幾克咖啡粉（`brews.dose`，g）。必填 | **粉量**：「量」可以是體積，手沖記的是重量。**豆量／豆重**：研磨前後重量相同，但這個欄位記的是放進濾杯的東西。**劑量**：翻譯腔 |
| **累積水量** | 這一段注完時磅秤上的數字（`brew_steps.cumulative_water`）。例：40 → 160 → 220。分段子頁的欄位標籤與摘要也是這四個字（2026-11-16 之前標籤寫「注到」） | **水量**（單獨出現）：分不出是這一段注了多少、還是注到多少。**累計水量**：同義，只留一個。**注水量**：容易讀成「這一注注了多少」，那是增量，不是累積值。差異區的標籤是「各段累積水量」，不是「各段水量」 |
| **增量水量** | 這一段本身注了多少，＝這段的累積水量 − 前一段的累積水量。衍生值，不存資料庫。介面上以「+120g」呈現 | **注水量**：同上，太容易和累積水量混淆，所以規格裡一律寫「增量水量」 |
| **總水量** | 最後一段的累積水量。衍生值，不存資料庫 | **總注水量**：多一個字不多資訊。**用水量**：聽起來包含溫杯、潤濕濾紙的水 |
| **粉水比** | 總水量 ÷ 粉重，顯示為「1:15.0」。衍生值；手法的 `default_ratio` 也是這個比值 | **水粉比**：順序反過來，會讓人懷疑分子分母是不是也反了。**比例**（單獨出現）：《02》比較表的示意圖曾寫「比例」，不知道是什麼的比例 |
| **水溫** | 注水時的水溫（`brews.water_temp`，°C） | — |

## 三、分段

| 使用的詞 | 精確指什麼 | 刻意不用的同義詞及原因 |
|---|---|---|
| **分段注水** | 一筆紀錄裡依序的每一注（`brew_steps`）。表單上那一區的標題 | **注水段**：沒有人這樣說。紀錄詳情頁的標題簡稱「分段」，那是同一個東西 |
| **段**、**第 N 段** | 分段注水裡的一筆。段號從悶蒸之後的第一個一般段落數起，沒有悶蒸時第一段就是「第 1 段」 | **段落**：只用在「段落備註」這個固定說法裡，其他地方用「段」。**第 N 注**：「注」是動作，「段」是紀錄的單位；模板的備註裡會出現「第一注」，那是在描述動作本身 |
| **注水** | 把水倒進濾杯的動作 | **給水**：規格裡曾經用過，和注水同義，只留一個。**沖水**：口語，不精確 |
| **悶蒸** | 第一段用少量水（通常是粉重的 2 到 3 倍）讓粉床濕透、排出二氧化碳（`step_type = 'bloom'`）。水量依粉重決定（`dose` 基準） | **預浸**：浸泡式沖煮的說法。**悶粉／開花**：口語，不統一。**四六法的第一注不是悶蒸**，不能叫悶蒸，資料上是 `pour` |
| **攪拌** | 用攪拌棒或湯匙攪動粉層。**介面上的攪拌標記已經移除**（2026-11-16）：需要的話寫在段落備註。舊紀錄裡 `step_type = 'stir'` 的段併進相鄰的段，備註補上「攪拌」這兩個字（《02》§5 區塊三） | **攪動**：同義，只留一個 |
| **搖晃（濾杯）** | 注完之後拿起濾杯旋轉搖晃，讓粉床平整。只出現在手法模板的備註與說明裡 | **晃動**：同義，只留一個。使用者既有紀錄的段落備註裡可能還有「晃動」（當初從模板帶入後存下來的），那是紀錄，不改。**「輕晃」不在此列**：它描述的是力道（五段式最後一段「輕晃濾杯」），不是搖晃的同義詞，保留 |
| **段落備註** | 某一段的自由文字（`brew_steps.note`） | — |

## 四、研磨

| 使用的詞 | 精確指什麼 | 刻意不用的同義詞及原因 |
|---|---|---|
| **研磨刻度** | 磨豆機面板上的讀數（`brews.grind_setting`）。簡稱「刻度」，只用在比較表欄位、時間軸這類空間不夠的地方，以及刻度規格那一行（「刻度 1–8」） | **研磨度**：指的是粉的粗細本身，那是結果；不同磨豆機的同一個刻度，粗細完全不同，這個欄位記的是讀數不是粗細。**粗細**：同理。**格數**：「格」只出現在型錄備註（「一圈 40 格」），描述面板構造 |
| **刻度範圍** | 型錄記載的面板最小到最大值（`grind_scale_min`／`max`） | — |
| **最小間隔** | 面板能停的最小一步（`grind_scale_increment`），例如 0.5、1 | **級距／步進**：工程用語 |
| **連續無段** | 面板沒有段落、可以停在任何位置（`increment` 為 null） | **無段**：型錄備註裡會出現，意思相同；介面的固定說明寫全「連續無段」 |
| **手沖常用** | 型錄記載的手沖實用範圍（`grind_scale_suggested_min`／`max`） | **建議範圍**：「建議」聽起來像系統替使用者決定 |

## 五、手法

| 使用的詞 | 精確指什麼 | 刻意不用的同義詞及原因 |
|---|---|---|
| **沖煮手法** | 一套分段注水的做法（`brew_methods`），選了會依粉重帶入分段。簡稱「手法」，用在空間不夠的地方 | **沖法**：只剩手法的別名裡還有，名稱裡已經拿掉。**沖煮法／沖煮方式**：同義，只留一個。**手沖手法**：這個產品只記手沖，「手沖」不承載資訊。**注水手法**：那是另一件事，見下一列 |
| **注水手法** | 注水時的繞圈方向、半徑、水柱大小、速度。只有 `brew_steps.pour_pattern`（中心、繞圈、螺旋）建了欄位，其餘三項不建；第一版介面都不露出 | 不能簡稱「手法」：會和沖煮手法混在一起 |
| **分段模板** | 手法裡記載每一段怎麼分水、停多久的比例資料（`brew_methods.step_template`） | **模板**單獨出現時要確定上下文是手法 |
| **手法名稱** | 三段式、四六法、五段式 Rao Spin、Perger 攪拌流、肥尾法 | 不帶「沖法」：選單的脈絡已經說明那是手法，每個名稱都重複一次只是雜訊。舊名稱（三段式沖法等）留在 `aliases` 供比對 |

## 六、豆子

| 使用的詞 | 精確指什麼 | 刻意不用的同義詞及原因 |
|---|---|---|
| **豆子**；量詞「**支**」 | 一包咖啡豆（`beans`）。「這支豆子」 | **咖啡豆**：可以，但導覽與標題用「豆子」。量詞不用「**隻**」（那是動物的量詞）、「款」「包」：介面上一律「支」 |
| **烘焙日期** | 豆袋上的烘焙日（`beans.roast_date`） | — |
| **養豆天數** | 沖煮日期 − 烘焙日期。衍生值，不存資料庫。卡片與比較表空間不夠時寫「養豆 N 天」「養豆」 | **養豆期**：指建議等待的區間（例如「養豆期 7–14 天」），不是已經過了幾天。**熟成天數**：少見。**賞味期**：是另一件事 |
| **烘焙度** | 淺焙、中淺焙、中焙、中深焙、深焙（`beans.roast_level`） | **焙度／烘焙程度**：同義，只留一個。選項一律用「X焙」，不寫「淺烘焙」 |
| **處理法** | 水洗、日曬、蜜處理等（`processing_methods`） | **處理方式／後製**：同義，只留一個 |
| **品種**、**產國**、**產區** | `varieties`、`countries`、`beans.region` | **產地**：分不出是國家還是產區 |
| **咖啡店名** | 豆子從哪裡買的、誰烘的（`beans.roaster`） | **烘豆商／烘焙商**：使用者多半是在店裡買的，記得的是店名 |
| **官方風味描述** | 豆袋或店家寫的風味（`beans.official_notes`） | **風味筆記**：會和使用者自己的「心得筆記」混淆 |
| **豆袋照片** | 豆子的照片（`beans.photo_path`），拍的是豆袋：上面有店家與標籤，看得出是哪一支、在哪裡買的。豆子表單的欄位標籤；分享頁全螢幕檢視的名稱（螢幕閱讀器唸的） | **豆子照片**：拍的不是豆子本身。**圖片**：太籠統，分不出是哪一張 |
| **縮圖**／**原圖** | **只在規格裡用**。原圖是存起來的那張豆袋照片（裁切、壓縮後，長邊 1600px）；縮圖是它旁邊另存的小檔（長邊 384px，《01》§7.1）。縮圖大小的地方載縮圖，原圖只用在豆子詳情的大圖、表單預覽與放大檢視 | **大圖／小圖**：「大圖」在豆子詳情頁另有所指（整頁寬的那張照片）。**原始照片**：會和「裁切前的照片」混淆——裁切前的那張根本不存（《02》§9），要說它時寫「裁切前的照片」 |
| **放大檢視** | **只在規格裡用**。點縮圖之後全螢幕顯示照片的那一層（`PhotoZoom`，《03》§4.14）。介面上沒有這四個字，螢幕閱讀器唸的名稱是「豆袋照片」 | **燈箱（lightbox）**：開發術語。**預覽**：暗示那是草稿（同「分享頁」那一列） |

## 八、紀錄與品飲

| 使用的詞 | 精確指什麼 | 刻意不用的同義詞及原因 |
|---|---|---|
| **照這次再沖一次**／**照上次再沖一次** | 複製一筆紀錄的參數與分段，開一張新表單。紀錄詳情頁寫「這次」，豆子詳情頁寫「上次」（永遠是最新那筆） | 按鈕不寫「複製紀錄」：使用者要的不是複製一份資料，是再沖一杯。規格裡這個流程叫「複製」 |
| **紀錄**（名詞）／**記錄**（動作） | 「紀錄」是記下來的那一筆東西：沖煮紀錄、這筆紀錄、新增紀錄、這杯紀錄。「記錄」是記下來這個動作：記錄停水時長、每週記錄目標、本月卡片的「記錄 N 筆」、累計卡片的「總共記錄 N 筆」。**標題、按鈕上指一筆資料的是名詞，用「紀錄」**（2026-11-17 寫成規則；既有的用法本來就是這樣分的） | 兩個字在一般用法裡常互通，所以最容易寫錯。Figma 的記錄表單區塊標題寫「這杯記錄」，介面照這條寫「這杯紀錄」 |
| **這杯紀錄**、**器材**、**沖煮**、**品飲** | 記錄表單的四個區塊標題（《02》§5）。2026-11-17 照 Figma 從「這一杯」「喝起來」改成「這杯紀錄」「品飲」 | **這一杯**（當表單的區塊標題）：前一版。結算頁第一杯的區塊標題仍是「這一杯」，那是另一個地方。**喝起來**：前一版，口語；規格裡這一組欄位本來就統稱「品飲」 |
| **收藏** | 「還想再沖一次」的標記（`brews.is_favorite`），以愛心圖示表示 | **最愛／喜歡**：同義，只留一個。規格裡的「愛心」指的是圖示 |
| **評分**、**強度**（酸質、甜感、醇厚、苦味）、**風味標籤**、**心得筆記** | 品飲欄位。規格裡這一組統稱「品飲」 | 強度的說明句是「請依照強弱程度填寫」，風味標籤的是「請選取感受到的風味」（2026-11-16 照 Figma；之前是「描述強弱，不是好壞」加「弱／強」） |
| **新增風味詞**、**輸入風味詞** | 風味標籤卡片最下面那一列：平常是動作「＋ 新增風味詞」，點了變成輸入列，提示字「輸入風味詞」，右邊的按鈕「新增」（2026-11-17） | — |
| **差異**、**和 M/D 那一杯相比** | 這筆與比較對象不同的地方（衍生值）。比較對象：複製來的是複製來源，否則是同一支豆子在它之前的最近一筆（《02》§7）。紀錄詳情與結算頁的區塊標題寫「和 M/D 那一杯相比」，M/D 是比較對象的沖煮日期 | **相對上一次**：前一版的標題（2026-10-06 改）。比較對象不一定是「上一次」——複製來源可能是很久以前那一杯 |
| **帶入** | 把既有的值填進表單：複製來源的參數、手法的分段模板、常用器材、按鈕下方的「帶入 3/12 那次的參數」 | **代入**：數學用語（代入公式），而且同一個動作兩種寫法會被當成兩件事 |
| **暫存**（暫存中、已暫存） | 表單內容自動存在這台裝置上的草稿（localStorage），還沒進資料庫 | **儲存**：那是按鈕的動作，寫進資料庫。狀態指示寫「已儲存」會讓人以為已經存好了，不必再按 |
| **儲存** | 按下按鈕，寫進資料庫 | **送出**：表單不是寄給誰。**保存**：同義，只留一個 |
| **上次的內容尚未儲存** | 暫存詢問的標題：隔了一段時間回到表單時，說明有一份還沒存進資料庫的內容（《02》§6）。陳述句，三張表單（沖煮、豆子、器材）與新增、編輯共用 | **上次有一筆沒存完，要繼續填寫嗎？**：前一版的問句。標題說明狀況、按鈕說明動作，問句把動作也放進了標題。**上次未完成的紀錄**：「紀錄」專指沖煮紀錄，豆子與器材表單上是錯的。**已暫存**：「暫存」是狀態指示用的詞；這裡要說的是「還沒存進資料庫」，所以是「尚未儲存」 |
| **繼續填寫**／**重新開始** | 暫存詢問的兩顆按鈕：接著填上次的內容（主要，右）／清掉暫存從空白開始（次要，左） | — |
| **範例** | 註冊時自動建立的那三筆資料（`is_sample`）。畫面上就是卡片與詳情頁上的那個「範例」標籤（《01》§13） | **示範資料**：多兩個字，而且「示範」聽起來像系統在教學；**假資料**：那三筆是真的、可以編輯也可以留著用，不是假的 |

## 九、導覽與動作

三個詞以前混在一起：同一個「取消」在表單頁右上角其實保留暫存、在器材表單真的丟棄、在就地新增是清空輸入。判斷的依據只有一條——**按下去會不會丟東西**（《03》§3）。

| 使用的詞 | 精確指什麼 | 刻意不用的同義詞及原因 |
|---|---|---|
| **總覽** | 分頁列第一格，也是 `/` 這一頁的標題：目標環、最近沖煮、本週最高分、累計、本月（《02》§4.1） | **首頁**：改版前的名稱（2026-10-01 改）。分頁改名之後同一個地方不能有兩個名字，介面與規格指稱這一頁時一律寫「總覽」；「首頁」只在描述改版前的樣子時出現。**看板、儀表板**：說的是這一頁的性質，規格裡描述它時可以用，不當它的名稱 |
| **紀錄**（分頁） | 分頁列第二格，也是 `/brews` 這一頁的標題：所有沖煮紀錄的列表。規格裡寫「紀錄分頁」，與一筆「紀錄」（沖煮紀錄）分開 | **沖煮紀錄**（當分頁名稱）：分頁列四格都是兩個字，而且「紀錄」在這個產品裡本來就專指沖煮紀錄。**時間軸**：指的是這一頁裡那串列表的樣子，規格裡用，不是頁面的名稱 |
| **返回** | 檢視型畫面左上角的 ‹。一律回上一頁，沒有上一頁時回父層：紀錄詳情回紀錄分頁、豆子詳情回豆子列表、設定回總覽（《03》§3）。不丟任何東西。只當圖示的無障礙名稱，畫面上不寫字 | **回豆子列表、回總覽**（放在頂部的文字連結）：返回的方向由規則決定，用圖示表達；寫成文字又放在頂部，會跟頁面動作混在一起 |
| **回總覽** | 全域錯誤頁、頁內的錯誤畫面、分享的失效畫面（已登入時）上的按鈕，目的地是 `/`。只留在這三處——那裡沒有分頁列，它是唯一的出口 | **回首頁**：改版前的文案。分頁改名後，同一個地方不能有兩個名字 |
| **離開** | 流程型畫面（表單）左上角的 ‹：離開這個流程，**暫存留著**，回來還在。站內有上一頁就退回上一頁，沒有才依網址決定目的地（《03》§3）。只當圖示的無障礙名稱 | **取消**：以前表單頁右上角寫「取消」，實際上什麼都沒丟，使用者卻以為按了就沒了。**返回**：同一個圖示，但「離開」提醒這裡是一個還沒完成的流程 |
| **刪除「名稱」**／**刪除這筆紀錄** | 刪除確認對話框的標題：陳述句、不加問號。豆子與器材放名稱並加「」（名稱常有空格，不加看不出動詞與名稱的界線）；紀錄沒有名稱，寫「刪除這筆紀錄」（《03》§4.8） | **刪除這支豆子？／刪除這個器材？／刪除這筆紀錄？**：前一版的問句標題 |
| **刪除** | 刪除確認對話框的確認按鈕。刪除的對象已經在標題裡，按鈕不重複 | **刪除這筆紀錄／刪除這支豆子／刪除這個器材**（按鈕）：前一版的按鈕文案，與標題重複。**確定**：沒說要做什麼。**刪掉**：口語（《03》§5.5） |
| **刪除後無法復原。** | 刪除確認內文的第一句，三種對象都一樣。有連帶影響時接第二句陳述句（《03》§4.8） | **刪掉之後沒辦法復原**：對話口吻（《03》§5.5）。**連同……一起刪掉**：同上，改成「……會一併刪除」 |
| **紀錄已儲存，分段儲存失敗。請再按一次儲存。** | 新增或編輯沖煮紀錄時，紀錄寫進去了、分段沒有。新增頁再按儲存會補寫同一筆，不會多出一筆（《02》§5）。後面括號只附原因、不附動作，例如「（無法連線到伺服器）」——同一則訊息不出現兩個「請」 | **紀錄存好了，但分段沒存進去**：前一版，對話口吻 |
| **電子郵件格式錯誤**／**欄位格式錯誤** | 輸入的格式不符（auth 的 `validation_failed`、Postgres 的 `22P02`） | **格式不對**：口語，與「電子郵件或密碼錯誤」同一個說法（《03》§5.5） |
| **歡迎來信 …** | 錯誤頁與頁內錯誤邊界上的聯絡句：「已記錄的資料不受影響，重試通常可以解決。如果一直出現同一組代碼，歡迎來信 rogerjiang01@gmail.com。」。**唯一保留溝通語氣的地方**（《03》§5.5 的例外） | **把它回報給我們**：前一版，沒有給聯絡方式 |
| **取消** | **會丟東西**的放棄：清掉就地新增填到一半的內容、不保留裁切中的照片、不執行刪除。一律用文字，不用圖示 | **離開、返回**：那兩個不丟東西。**關閉**：那是收起一則頁面提示（見下），不放棄任何東西。「取消常用」已經沒有了（2026-11-17「設為常用」改成開關） |
| **重試** | 讀取失敗時再讀一次：錯誤頁、頁內的錯誤邊界、詳情頁與編輯頁的讀取失敗，全部同一個詞 | **重新載入**：以前錯誤頁用這個，頁內用另一個，同一個動作兩種叫法。**重試這一頁**：「這一頁」不承載資訊 |
| **關閉** | 收起一則**不會自己消失**的頁面提示：分享建立失敗、無法複製。不放棄任何東西。一律用文字，不用 × 圖示（《03》§3 的 × 只用在列表內的單項移除） | **知道了**：只說看過了，但建立失敗那則旁邊還有「再試一次」，兩個按鈕要是同一種性質的動作。**取消**：這裡沒有要放棄的東西 |
| **前往紀錄** | 分享頁上只有分享者本人看得到的連結，回到自己那筆紀錄的詳情頁（《02》§7.2） | **查看紀錄／我的紀錄**：前者「查看」不承載資訊（點連結本來就是去看），後者在一個只有本人看得到的橫幅裡，「我的」是多的。**編輯**：那是到編輯頁，不是同一件事 |

## 十、分享

這一組詞全部是新的（《01》§14、《02》§7.1、§7.2）。**「分享」在中文裡太容易滑向「公開」「發布」**，而這個功能刻意不是那個——沒有動態牆、沒有人找得到別人的紀錄，拿到連結才看得到。用詞要守住這個差別。

| 使用的詞 | 精確指什麼 | 刻意不用的同義詞及原因 |
|---|---|---|
| **分享** | 把一筆沖煮紀錄變成一個連結，傳給誰由使用者自己決定（`brew_shares`）。動詞與按鈕文案都是這兩個字 | **公開／發布／上架**：這三個都暗示「放到某個大家看得到的地方」，但這個功能沒有那個地方。`brews.visibility = 'public'` 是資料庫的值，不是介面用詞，而且分享並不改它（《01》§3.5）。**分享出去**：多兩個字不多資訊 |
| **停止分享** | 讓目前的連結永久失效。之後再分享會是新的連結。**第一版不做**（《02》§11），介面上不出現；詞先定好，同義詞照樣不用 | **取消分享**：「取消」在本表第九節專指「會丟東西的放棄」（放棄填到一半的內容），而停止分享不是放棄一個正在進行的動作，是把一個已經生效的東西關掉。**關閉分享**：「關閉」在這個產品裡沒有其他用例（§3 已把「關閉 ×」移出圖示清單），為它新增一個用法只會讓人猜。**收回／解除分享／刪除連結**：三種說法同一件事；「刪除」還會讓人以為紀錄本身要被刪掉 |
| **分享連結** | 那一串網址（`/s/[code]`）。介面上通常不寫這四個字，只在「複製連結」「已複製連結」「連結目前無法開啟」這類句子裡以「連結」出現 | **公開連結**：同上，沒有「公開」這件事。**網址／URL**：使用者傳給朋友的東西，口語叫連結 |
| **分享頁** | 朋友看到的那一頁（`/s/[code]`）。**只在規格裡用**，介面上不出現這三個字 | **公開頁／預覽頁**：前者同上；後者暗示那是草稿的預覽，但朋友看到的就是正式的、即時的內容 |
| **分享心得筆記** | 分享對話框「選項」下的勾選框，決定**這一次**送出去的連結要不要帶出心得筆記（`brew_shares.include_notes`）。每次打開都預設不勾；建立之後不能改（《02》§7.1） | **包含心得筆記**：前一版的用詞，那時它是一條連結可以反覆切換的設定。**公開心得筆記／顯示心得筆記**：前者同上；後者聽起來像只是畫面上藏起來，但實際上沒勾時讀取函式根本不回傳（《01》§14.2），差別是實質的 |
| **已複製連結** | 按下「複製連結」，或系統分享失敗而改成複製之後的回饋。對話框關閉後出現在頁面底部，約兩秒後收起 | **已複製到剪貼簿**：「剪貼簿」是系統的語言不是使用者的語言（§5.1）。**複製成功**：「成功」是系統在報告自己 |
| **這筆分享已經無法查看** | 紀錄已刪除、代碼不存在，兩種情況共用的一句話 | **連結已失效／找不到這個頁面／無權查看**：第一個把原因說成是連結壞了，第二個像 404，第三個暗示「你不夠格，換個身分就看得到」——三個都在猜原因，而規格刻意不分原因（《02》§7.2） |
| **你分享的紀錄** | 分享者本人打開自己的連結時，頂端那一列只有他看得到的橫幅 | **預覽模式／你正在預覽**：「預覽」暗示這是草稿或模擬，但他看到的就是朋友看到的東西。**只有你看得到這一列**：那是在解釋實作 |
| **分享紀錄** | 分享對話框的標題 | **分享這筆紀錄**：多兩個字不多資訊 |
| **選項** | 分享對話框裡「分享心得筆記」上方的小標，分組標題的樣式。這筆紀錄沒有心得時連同勾選框一起不出現 | **設定**：「設定」在這個產品裡是總覽齒輪那一頁，而這裡的選擇只屬於這一次傳送，不是一項設定 |
| **複製連結** | 分享對話框的按鈕：當場產生一條新連結並複製。支援系統分享時是左邊的次要按鈕；不支援時是唯一一顆，而且是主要按鈕 | **複製網址**：同「分享連結」那一列，口語叫連結。**拷貝**：同義，只留一個 |
| **分享建立失敗，連結目前無法開啟** | 按下「分享」或「複製連結」之後建立請求失敗。連結已經送出去了，這句話說的是那條連結現在的狀態。對話框已經關了，顯示在頁面層級、不自動消失，附「再試一次」與「關閉」（《02》§7.1） | **分享沒有建立成功，剛才那個連結還不能用**：前一版的文案 |
| **再試一次** | **重送一個失敗的寫入**：建立分享的請求（用同一個代碼） | **重試**：那是「讀取失敗時再讀一次」（本表第九節），這裡是再寫一次，不是同一件事 |
| **無法複製，請長按連結手動複製** | 系統分享與複製都失敗時，顯示在連結本身上方的說明 | **複製失敗**：「失敗」只說了出錯，沒說接下來怎麼辦。**請手動複製**：沒說怎麼手動——手機上是長按 |
| **放大豆袋照片** | 分享頁豆袋照片縮圖的按鈕名稱。**只給螢幕閱讀器**（`aria-label`），畫面上看不到這幾個字。點下去全螢幕顯示同一張照片（《03》§4.13.4）；放大後照片的替代文字是豆名 | **查看照片**：縮圖本身也是在看照片，沒說出「變大」這件事。**檢視照片**：書面語。**預覽**：暗示那是草稿（同「分享頁」那一列）。**豆袋照片**（只有名詞）：螢幕閱讀器唸成「豆袋照片，按鈕」，按下去會怎樣要使用者自己猜 |

## 十一、總覽與結算頁

2026-10-06 加入（首頁改版第二階段，《02》§4.1、§4.4、§5「結算頁」）。這一組文案照規格逐字使用。總覽與結算頁不放規定以外的說明或鼓勵性質的句子；卡片名稱與星期這類標籤不在此限。

| 使用的詞 | 精確指什麼 | 刻意不用的同義詞及原因 |
|---|---|---|
| **每週記錄目標** | 使用者自己定的一週要記幾杯（`weekly_goals.cups`）。目標設定頁的標題是「設定每週記錄目標」，修改目標的對話框標題是「每週記錄目標」 | **每週目標**：少了「記錄」，像是在定喝幾杯咖啡。**挑戰**：第二批另有「每月挑戰」，不能混用 |
| **杯** | 每週目標的計數單位：「3 杯」「超過 1 杯」；最近沖煮的「第 N 杯」。一杯就是一筆沖煮紀錄 | **次、筆**（當目標的單位）：「筆」留給紀錄的總數（「N 筆紀錄」「第 N 筆紀錄」「總共記錄 N 筆」，以及本月的「記錄 N 筆」——2026-11-16 照 Figma 從「杯」改成「筆」），每週目標的進度一律用「杯」 |
