4. **移除攪拌標記**，需要的話寫在備註。這批不改資料庫：新的介面不能再新增攪拌。

**其他**

6. **輸入框的錯誤狀態改用形狀區分**：錯誤時在輸入框右側加 Lucide 的 `circle-alert`，錯誤訊息前也加同一個圖示。綠底和淺色底都這樣做。

## 二、計畫（2026-11-16 回報的內容）

### 先更正的兩件事

- **Frame 72 不是「不記停水時長」的版本。** 它是另一種排法：累積水量和停水時長並排在同一列（各佔一半），最後一段只有累積水量。
  兩個節點都有停水時長。子頁照沖煮詳細頁（一欄一列）；不記停水時長時，就是每段少掉那一列。
- **主表單進入子頁的那一列，Figma 寫的是「編輯」，不是「開啟碼錶」。**「開啟碼錶」是另一張獨立的卡片，主表單和子頁最下方各有一張。

**卡片分組**照 Figma，一共 13 張（現在是 4 張）：

| 器材 | 磨豆機＋研磨刻度／濾杯＋手沖壺／濾紙與分享壺（收合） |

### 攪拌標記

查到的現況：

- **手法模板裡沒有攪拌步驟**：seed 與之後的 migration 裡全部 72 個步驟只有悶蒸 15 個、注水 57 個
- **既有的攪拌資料只會來自使用者自己標的**。正式庫有幾筆查不到（沒有連線），實作時附一段查詢
- 攪拌現在出現在三個地方：編輯器的切換鈕、紀錄詳情、分享頁（後兩個是 `StirIcon`）
- `waterOrderHints` 對攪拌段有特例（不注水，不參與遞減的比對）；累積水量相等本來就不提示，轉成一般段不會多出提示

做法：

- **編輯器**：拿掉切換鈕與 `StirIcon`
- **載入表單時**（編輯、照這次再沖一次）：攪拌段轉成一般段，備註前面補上「攪拌」。這個轉換算表單的初始狀態，不觸發暫存
- **顯示**（紀錄詳情、分享頁）：還沒被編輯過的攪拌段，在備註的位置顯示「攪拌」文字，不用圖示
- **資料庫**：這批不動，`step_type` 的 `stir` 留著。清理用的 migration 記進 CLAUDE.md；
  它是覆寫使用者資料的 `update`，上線時照不可逆 migration 的規則報告
- 凍結清單第 1 項（攪拌標記是否需要獨立圖示）因此結案

### 開場動畫

- **首圖**：Cover 的 4 張插畫從 Figma 匯出，用本機的 `cwebp` 轉成 WebP、每張壓到 200 KB 以內，
  放在帶版本號的目錄，設一年的不可變快取（和字型同一套做法）
- **隨機**：這個站是伺服器渲染的，由伺服器挑一張寫進 HTML 並預先載入，瀏覽器不必等程式就看得到。

- **已登入**：總覽的資料到了就淡出，**最少 0.3 秒、最多 0.8 秒**
- **減少動態**：不做位移，只淡入淡出

**hydration 對不上的原因**

這次的環境比上一輪真：本機跑 `TZ=UTC` 的 dev server 與正式版建置（模擬 Vercel），瀏覽器設成 Asia/Taipei、390px；

- **使用者看得到的後果**（正式版建置裡截圖確認）：正式版的 Vue 只換掉標籤不同的節點，**不修屬性的差異**。`/goal` 的 `<main>` 沿用了 A 頁的 class 與 style，

  修完之後：有目標、沒有目標兩種帳號全站 0 個警告；`curl` 看到 302；從分享頁點分頁列去 `/beans`，站內換頁一樣導到 `/goal`

**和時間有關的算繪：沒有問題**

- 每一頁的資料都在 `onMounted` 才查，伺服器只算繪骨架。「本週」「本月」「今天」、日期、時刻、養豆天數全部在瀏覽器裡算，用的是使用者的時區
- 程式裡所有 `new Date()` 逐一看過：會在伺服器執行的只有總覽與結算頁的 `now`，但伺服器那時只畫骨架、沒有用到它；
  瀏覽器在 `onMounted` 重算一次。記錄表單的預設時間（`toLocalInput(new Date())`）在 `ready` 之後才畫，也只在瀏覽器
- 實際驗過：假資料放了兩筆在台灣的凌晨（UTC 是前一天），豆子詳情的比較表顯示的是台灣的日期（`11-09T16:15Z` → 11/10、`11-13T23:40Z` → 11/14）
- 現在沒問題靠的是「資料只在瀏覽器查」這條慣例。之後把任何和時間有關的值搬到伺服器算繪之前要先問（CLAUDE.md 記了）
- 沒有試的：伺服器端 token 過期要換新的那一刻（假伺服器沒有做換 token 的端點）

### 1. 下拉列（`SelectField` 改用 `SheetPill`）

**原因**：烘焙度、器材類型、沖煮手法是原生 `<select>`，膠囊（`.sheet-pill`）直接畫在 `select` 上。原生 `select` 的寬度跟著**最長的選項**走（烘焙度是「中深焙」），所以選了「淺焙」右邊留一段空；
沒選值時「選填」外面的綠框，推測是全站的 `:focus-visible` 焦點框（`--accent`，2px）：點了之後焦點留在 `select` 上。

**做法**：`SelectField` 加 `text`、`empty` 兩個 prop。給了 `text` 時，看得到的是 `SheetPill`（和產國、處理法、品種、器材型號、豆子同一個元件），
原生控制項攤成透明（`position: absolute; inset: 0; opacity: 0`）蓋在上面——點膠囊的任何地方都是點到原生控制項，手機上照樣開系統的選擇器。
聚焦時膠囊的文字換成 `--accent-text`（和下拉開著同一個狀態），原生控制項的焦點框跟著透明看不到。

### 發現的事：Playwright 的 WebKit 畫得出 corner-shape

Playwright 內建的 WebKit（27.2）`CSS.supports('corner-shape', 'squircle')` 是 true，也畫得出來。它是開發中的版本：**正式版的 Safari 到 27.2 都還不支援**，Safari Technology Preview 251（2026-08）起才有。
所以「iPhone 上看不到」目前仍然成立，但等正式版 Safari 出了就會改變；那時要回來在 iPhone 上看一次。《03》§2.3 記下了這一點，也記下 Playwright 的 WebKit 截圖不能代表 iPhone 現在的樣子。
調整頁上的說明照使用者的寫法，加上「正式版」三個字；另外有一行即時偵測這個瀏覽器支不支援。
