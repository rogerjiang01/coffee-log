## 一、決定（2026-11-25，使用者確認）

1. **加 `viewport-fit=cover`**：原本沒有，`env(safe-area-inset-*)` 在 iPhone 上一律是 0——加到主畫面全螢幕開啟時，分頁列壓在底部的橫線上，幾乎點不到。
   驗收：加到主畫面時整個分頁列（含文字）在橫線之上至少 8px，每一格完整可點；頂端與開場不被狀態列蓋住；橫向的左右安全區。
   **同一天實機看過之後改了下緣**，見下面第 6 項
2. **器材的圖示照 Figma 的平頭直角**，《03》§3 記一條例外：分頁列這組圖示不套用圓頭規則
3. **圖示來源**：home、brew 是 Google Material Symbols（Apache 2.0）；bean 是 Iconify（圖示集當時待補，見第 7 項）；equip 是使用者自己畫的。記在 `NOTICE.md`
4. **選中那一格的字重 400**（照 Figma；原本 500）
5. **轉角**：`--corner-tab-bar`、`--corner-tab-indicator`，預設 `superellipse(1.2)`，加進 `/dev/corners`。**同一天改成 `round`**，見第六節
6. **下緣改成對齊 iOS 原生的浮動分頁列**（2026-11-25，實機看過之後）：原本是「安全區之上再 8px」，iPhone 上離螢幕底 42（34 + 8）。
   使用者量了實機截圖：Laeta 約 40pt，Apple 健身與 Instagram 的浮動分頁列約 20pt，左右三者都約 20pt——Laeta 浮得比原生的高一倍。
   改成 `max(12px, calc(env(safe-area-inset-bottom) - 14px))`：iPhone（安全區 34）是 20，和原生一致；沒有安全區的裝置與橫向（安全區 21，21 − 14 = 7）是 12。
   **理由是對齊 iOS 原生的浮動分頁列，不是「安全區之上再加多少」**：分頁列的下緣會落在安全區裡（和原生一樣），文字仍然在 home indicator 之上。
   浮動按鈕、底部空白、分享提示都從分頁列頂端往上算，跟著一起下移 22，間距（12／16／24）不變
7. **bean 的來源**：Iconify 的 `streamline-plump:coffee-bean`，Streamline 的 Plump free icons，授權 CC BY 4.0（要標作者、註明修改，寫在 `NOTICE.md`）

我自己判斷、使用者同意的：四顆浮動新增按鈕一起移到分頁列上方（豆子、器材的也會被新的分頁列壓到）；寬螢幕上分頁列與按鈕對齊內容欄；
底部留白只有一個基準 token、只在 `app.vue` 留；焦點框畫在格子內側。

## 三、安全區有處理的地方

| 哪裡 | 做法 |
|---|---|
| 頁面內容 | `body` 的 padding：上（狀態列）、左右（橫向的瀏海）。下由各頁留 |
| 分頁列、浮動新增按鈕、分享的頁底提示 | `--tab-bar-bottom`、`--fixed-left`／`--fixed-right` |
| 置中的對話框 | 四邊 `max(20px, 安全區)` |
| 全螢幕面板（器材選擇器、分段子頁、裁切） | 底色鋪滿，內容往內縮四邊的安全區 |
| 照片放大 | 原本就有 |
| 下拉的浮層 | 往下開時停在 home indicator 之上（`useAnchoredPanel` 量安全區） |
| 登入、註冊 | 首圖鋪滿（抵銷 body 的 padding），logo 與表單往內縮 |
| 目標設定頁 | 「開始」離 home indicator 至少 12px |

狀態列維持 `default`：加到主畫面時頁面從狀態列下面開始，頂端的安全區是 0。`body` 仍然讓出 `safe-area-inset-top`，之後改成 `black-translucent` 也不會被蓋住。

順手修的：`useInputModality` 原本把 Option＋Tab 當成「按修飾鍵」不算鍵盤操作，但 Safari 預設 Tab 跳不到連結、要 Option＋Tab——分頁列的四格是連結，用 Safari 鍵盤操作的人會看不到焦點框。改成 Tab 不論有沒有修飾鍵都算。

## 五、iPhone 實機要檢查的項目

Playwright 模擬不出安全區、狀態列與 home indicator，這些只能在 iPhone 上看。用 `redesign` 的 Vercel 預覽網址。

**加到主畫面之前要先刪掉舊的圖示再重新加**：主畫面的 web app 會記住當時的 viewport 設定，不重新加的話可能還是舊的行為。

### A. 加到主畫面、全螢幕開啟（這次最重要）

1. **分頁列的下緣離螢幕底約 20pt**，和 Apple 健身、Instagram 的浮動分頁列同高；文字在橫線之上（分頁列的下緣會落在安全區裡，和原生一樣）
2. **四格都點得到**：點每一格的上緣、下緣（文字那裡）、左右兩端，都會切換。分頁列最下面約 14pt 在 home indicator 的手勢區裡：
   點那裡要能切換，不會被系統當成「回主畫面」（原生的浮動分頁列也在同樣的位置，應該一樣）
3. 切換分頁時沙色膠囊滑過去；從紀錄詳情返回紀錄列表，膠囊不動、不閃
4. **頂端**：總覽、紀錄、豆子、器材、設定、紀錄詳情的標題沒有被狀態列（時間、電量）蓋住
5. **開場**：打開時的首圖與 logo 沒有被狀態列蓋住，logo 位置和之前一樣；淡出之後總覽沒有跳動
6. **登入頁**（登出後）：首圖鋪滿整個畫面，上面、下面都沒有色帶
7. **浮動新增按鈕**在分頁列右上方、離分頁列約 12pt，右緣和分頁列對齊；列表捲到底，最後一張卡片完整露在按鈕上面
8. **紀錄詳情、豆子詳情捲到底**：最後的「刪除」完整露在分頁列上面
9. **分享**：紀錄詳情 → 分享 → 複製連結，「已複製連結」出現在分頁列上方，不壓在分頁列上
10. **表單**：新增紀錄捲到底，「儲存」不壓在橫線上；器材選擇器的「確定」、裁切的「取消」「確認裁切」、分段子頁的內容不壓在橫線上，標題列不被狀態列蓋住
11. **下拉**（例如豆子表單的產國，捲到靠近畫面底部再打開）：選單的最後一項不壓在橫線上
12. **目標設定頁**（新帳號才會看到）：「開始」不壓在橫線上
13. **橫向**（轉成橫的）：頁面的文字、分頁列、浮動按鈕都沒有被瀏海或圓角切到；左右兩側是頁面底色，沒有黑邊或白邊

### B. Safari 瀏覽器開啟

1. 網址列在下方（iOS 預設）時：分頁列在網址列之上，不被網址列蓋住；捲動讓網址列縮小之後，分頁列跟著落到 home indicator 之上，不壓在橫線上
2. 四格都點得到；點最下面那一排不會叫出 Safari 的網址列而沒切換（如果會，記下來）
3. 上面 A 的 3、7、8、9、11 各看一次
4. 橫向：同 A 的 13
5. （有的話）網址列在上方的設定：分頁列在 home indicator 之上

### C. 其他

- 減少動態（設定 → 輔助使用 → 動作 → 減少動態）打開時，切換分頁膠囊直接出現在新的那一格，不滑

## 六、分頁列兩端改成正半圓（2026-11-25，實機比對之後）

使用者放大比對 iPhone 實機截圖：iOS 健身、Instagram 的浮動分頁列兩端是完整的半圓（弧線的水平寬度約等於高度的一半），
Laeta 的分頁列與選中的膠囊兩端明顯較扁，約只有八成。左右邊距與高度三者相近。

**量到的值**（390 寬、總覽）：

| | Chromium 159 | Playwright 的 WebKit（UA 寫 Version/27.2） |
|---|---|---|
| 分頁列 | 高 64、`border-radius` 32px（剛好一半）、`corner-shape: superellipse(1.2)` 生效 | 同左 |
| 選中的膠囊 | 高 56、`border-radius` 28px（剛好一半）、`corner-shape: superellipse(1.2)` 生效 | 同左 |
| `CSS.supports('corner-shape', 'superellipse(1.2)')` | true | true |

**圓角本身沒有錯**，兩端變扁只可能來自 `corner-shape`：superellipse 的 K 大於 1 時，轉角的曲線更貼近直角，弧線看起來比半圓短。

**iPhone 上的 Safari 有沒有生效，我們這邊驗證不了**：Playwright 的 WebKit 是開發中的版本（2026-11-19 就確認它畫得出 `corner-shape`），不代表正式版。
公開資料：Safari Technology Preview 251（2026-08）先加入；**Safari 27.3 beta 的發行說明列了「Added support for the corner-shape property」**；
沒有找到已經出貨的正式版。所以：

- iPhone 若是 **iOS 27.3 beta**（或之後的正式版）：`superellipse(1.2)` 有生效，這就是兩端變扁的原因，改成 `round` 會修好
- iPhone 若是 **27.2 以前的正式版**：`corner-shape` 被忽略，畫出來本來就是正半圓，改成 `round` **不會有任何變化**——那兩端看起來扁要另找原因

**確認方法**：設定 → 一般 → 關於本機看 iOS 版本；或在預覽網址上看這次改完之後兩端有沒有變。

**修正**：`--corner-tab-bar`、`--corner-tab-indicator` 改成 `round`，圓角維持高度的一半；`/dev/corners` 的預設改成 1（round）。

**其他套了 superellipse 的膠囊：決定維持，不改成 `round`**（2026-11-25 使用者決定）。在支援 `corner-shape` 的 iPhone 上同樣會比正半圓扁，
但它們不和系統的分頁列並排比較，維持 11-19 在 `/dev/corners` 調好的值。**只有分頁列與選中的膠囊用 `round`**。當時列出的範圍：

| token | 元素 | 高度／圓角 | 值 |
|---|---|---|---|
| `--corner-card-pill` | 只有一列的表單卡片（心得筆記、收藏、設為常用、已喝完、登入與註冊的欄位） | 56／28 | 1.2 |
| `--corner-card-pill-tall` | 只有一列、裡面有膠囊的卡片（沖煮時間、分段子頁的沖煮手法） | 65／32.5 | 1.2 |
| `--corner-block-button` | 滿寬的實心與外框按鈕（儲存、照這次再沖一次、編輯…） | 56／28 | 1.2 |
| `--corner-sheet-pill` | 下拉與日期的膠囊、沖煮時間的分秒框 | 34／17 | 1.1 |
| `--corner-chip` | 風味標籤（`border-radius: 9999px`，畫出來是高度的一半） | 正膠囊 | 1.1 |
| `--corner-toggle` | 開關的軌道與圓鈕（`rounded-full`） | 正膠囊／正圓 | 1.1 |
| `--corner-bar` | 總覽、目標設定的每日長條（`rounded-full`） | 正膠囊 | 1.1 |

1.2 的三種（單列卡片、滿寬按鈕）偏移最明顯；1.1 的差異較小。卡片（`--corner-card-ml`／`md`／`lg`，1.1）不是膠囊，不在這張表。
