## 一、決定（2026-11-25，使用者確認）

1. **加 `viewport-fit=cover`**：原本沒有，`env(safe-area-inset-*)` 在 iPhone 上一律是 0——加到主畫面全螢幕開啟時，分頁列壓在底部的橫線上，幾乎點不到。
   驗收：加到主畫面時整個分頁列（含文字）在橫線之上至少 8px，每一格完整可點；頂端與開場不被狀態列蓋住；橫向的左右安全區
2. **器材的圖示照 Figma 的平頭直角**，《03》§3 記一條例外：分頁列這組圖示不套用圓頭規則
3. **圖示來源**：home、brew 是 Google Material Symbols（Apache 2.0）；bean 是 Iconify（**圖示集待使用者補**）；equip 是使用者自己畫的。記在 `NOTICE.md`
4. **選中那一格的字重 400**（照 Figma；原本 500）
5. **轉角**：`--corner-tab-bar`、`--corner-tab-indicator`，預設 `superellipse(1.2)`，加進 `/dev/corners`

我自己判斷、使用者同意的：四顆浮動新增按鈕一起移到分頁列上方（豆子、器材的也會被新的分頁列壓到）；寬螢幕上分頁列與按鈕對齊內容欄；
底部留白只有一個基準 token、只在 `app.vue` 留；焦點框畫在格子內側。

## 三、安全區有處理的地方

| 哪裡 | 做法 |
|---|---|
| 頁面內容 | `body` 的 padding：上（狀態列）、左右（橫向的瀏海）。下由各頁留 |
| 分頁列、浮動新增按鈕、分享的頁底提示 | `--tab-bar-bottom`、`--fixed-left`／`--fixed-right` |
| 置中的對話框 | 四邊 `max(20px, 安全區)` |
| 全螢幕面板（器材選擇器、分段子頁、裁切） | 底色鋪滿，內容往內縮四邊的安全區 |
| 照片放大 | 原本就有 |
| 下拉的浮層 | 往下開時停在 home indicator 之上（`useAnchoredPanel` 量安全區） |
| 登入、註冊 | 首圖鋪滿（抵銷 body 的 padding），logo 與表單往內縮 |
| 目標設定頁 | 「開始」離 home indicator 至少 12px |

狀態列維持 `default`：加到主畫面時頁面從狀態列下面開始，頂端的安全區是 0。`body` 仍然讓出 `safe-area-inset-top`，之後改成 `black-translucent` 也不會被蓋住。

順手修的：`useInputModality` 原本把 Option＋Tab 當成「按修飾鍵」不算鍵盤操作，但 Safari 預設 Tab 跳不到連結、要 Option＋Tab——分頁列的四格是連結，用 Safari 鍵盤操作的人會看不到焦點框。改成 Tab 不論有沒有修飾鍵都算。

## 四、Playwright 驗證（桌面的 Chromium 與 WebKit，375×812、320×568、1024×800）

腳本在 `tmp-screenshots/tab-bar/shots.mjs`（不進版本庫），借用圓角盤點的假 Supabase，不連正式庫。**模擬不出安全區**（`env()` 一律是 0），所以下緣都是 12px 的情況。

兩個引擎結果相同：

| 檢查 | 結果 |
|---|---|
| 分頁列 | 375 寬：左右 20、下緣 12、335×64；320 寬：280×64。每格 81.75×56（320 寬 68×56） |
| 選中的格子 | 七頁（總覽、紀錄、豆子、器材、紀錄詳情、豆子詳情、設定）都亮對；字重 400 |
| 重新整理、直接打開 | 七頁都沒有觸發膠囊的 transition（0 次），第一次畫出來就在位置上 |
| 切換 總覽 → 豆子 | transform 的 x 從 0 逐格到 163.5（中間 10 個值），約 175ms |

| 1024 寬 | 分頁列 680 寬、左右 172，和內容欄一致；浮動按鈕右緣 172 |

## 五、iPhone 實機要檢查的項目

Playwright 模擬不出安全區、狀態列與 home indicator，這些只能在 iPhone 上看。用 `redesign` 的 Vercel 預覽網址。

**加到主畫面之前要先刪掉舊的圖示再重新加**：主畫面的 web app 會記住當時的 viewport 設定，不重新加的話可能還是舊的行為。

### A. 加到主畫面、全螢幕開啟（這次最重要）

1. **分頁列整個在底部的橫線之上**，文字的下緣到橫線至少 8px（目測：分頁列下緣離螢幕底約 42pt）
2. **四格都點得到**：點每一格的上緣、下緣（文字那裡）、左右兩端，都會切換；最下面那一排不會被系統當成「回主畫面」的手勢
3. 切換分頁時沙色膠囊滑過去；從紀錄詳情返回紀錄列表，膠囊不動、不閃
4. **頂端**：總覽、紀錄、豆子、器材、設定、紀錄詳情的標題沒有被狀態列（時間、電量）蓋住
5. **開場**：打開時的首圖與 logo 沒有被狀態列蓋住，logo 位置和之前一樣；淡出之後總覽沒有跳動
6. **登入頁**（登出後）：首圖鋪滿整個畫面，上面、下面都沒有色帶
7. **浮動新增按鈕**在分頁列右上方、離分頁列約 12pt，右緣和分頁列對齊；列表捲到底，最後一張卡片完整露在按鈕上面
8. **紀錄詳情、豆子詳情捲到底**：最後的「刪除」完整露在分頁列上面
9. **分享**：紀錄詳情 → 分享 → 複製連結，「已複製連結」出現在分頁列上方，不壓在分頁列上
10. **表單**：新增紀錄捲到底，「儲存」不壓在橫線上；器材選擇器的「確定」、裁切的「取消」「確認裁切」、分段子頁的內容不壓在橫線上，標題列不被狀態列蓋住
11. **下拉**（例如豆子表單的產國，捲到靠近畫面底部再打開）：選單的最後一項不壓在橫線上
12. **目標設定頁**（新帳號才會看到）：「開始」不壓在橫線上
13. **橫向**（轉成橫的）：頁面的文字、分頁列、浮動按鈕都沒有被瀏海或圓角切到；左右兩側是頁面底色，沒有黑邊或白邊

### B. Safari 瀏覽器開啟

1. 網址列在下方（iOS 預設）時：分頁列在網址列之上，不被網址列蓋住；捲動讓網址列縮小之後，分頁列跟著落到 home indicator 之上，不壓在橫線上
2. 四格都點得到；點最下面那一排不會叫出 Safari 的網址列而沒切換（如果會，記下來）
3. 上面 A 的 3、7、8、9、11 各看一次
4. 橫向：同 A 的 13
5. （有的話）網址列在上方的設定：分頁列在 home indicator 之上

### C. 其他

- 選中那一格的文字沒有變粗（和未選同一個字重），切換時字不跳
- 減少動態（設定 → 輔助使用 → 動作 → 減少動態）打開時，切換分頁膠囊直接出現在新的那一格，不滑
- Android（如果手邊有）：分頁列下緣離螢幕底約 12dp，不被手勢列蓋住
